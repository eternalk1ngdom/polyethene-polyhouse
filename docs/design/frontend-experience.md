# 前端体验参考

更新：2026-11-03。记录用户已认可的方案二与工具页经验，供宏观设计、跨页面改版或大规模前端查漏时按需读取；日常问答、后端工作和局部修复不默认加载。工程约束仍以 [AGENTS.md](../../AGENTS.md) 为准，实施状态看[当前日志](../dev-log/v1.0-dev.12.md)。

## 已确认的方向

| 关注点 | 本项目的取舍 |
| --- | --- |
| 视觉 | 沿用[方案二](frontend-v2.md)：白底、墨色主体、粉色交互点缀。首页搜索光晕是已认可的展示特色，业务表单保持克制。 |
| 信息层级 | 初次进入即可完成基本任务；低频参数、管理和详细统计按需展开。折叠摘要提示已生效的非默认设置，重要错误与待确认来源应能被发现。 |
| 文件入口 | 同类工具使用一致的点击／拖入区域；文件和目录能力在同一区域组织，避免不同风格的入口上下堆叠。兼容不足时降级到真实可用能力，不伪装支持。 |
| 文案 | 先说用户需作的决定和实际后果；默认区只留必要限制、输出变化和隐私说明。详细原理放在对应高级项或按需帮助，不为缩句牺牲准确性。 |
| 反馈 | 悬停轻、按下明确，键盘焦点清晰且不重复描边；工具投放框用柔和粉色虚线，键盘在原框提示。首页跳转入口可用深粉反馈。 |
| 布局 | 同类页面统一对齐线与尺度，允许内容造成自然高度差。当前两工具参考最大1320px、900px双栏切换；登录窗、个人页、管理表格按内容判断，不机械套宽度。 |
| 状态 | 展开与收起只管理显示，不清空输入、重置参数或打断任务；处理、取消、失败、下载与来源确认沿用真实状态。 |

## 使用方法

- 开始跨页面设计时先确认目标、相邻区域、共享控件和已认可特色，再结合源码选择最小改动；外部网站和UI技能用于辅助判断，不直接替代本项目决定。
- 宏观复核重点看：基本任务是否清楚、次要功能是否挤占主流程、文案是否帮助决策、同类控件是否一致、小屏和键盘是否可操作。具体执行和验证遵循根契约，不在此复制检查清单。
- 新经验优先修订相应行；未体验确认的想法留在阶段日志，不升级为统一风格。顶部介绍区高度、更多高级项分组目前仍是候选。
