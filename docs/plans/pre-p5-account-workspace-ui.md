## 1. 判断与范围

用户反馈合理：按任务分区、明确工作台导航和统一焦点反馈属于信息组织与一致性维护，符合本项目当前规模。个人中心和工作台是并列入口，工作台内部账号管理/审核/开户仍存在清晰的任务关系；不应为了强调并列而取消工作台内部导航。

分类切换不是所有网站唯一正确的布局，但适合本项目不断增加的账号功能。将改版放在 P5 综合验收前可以避免验收旧版后马上大改；实现时仍必须做局部回归，不能理解为改版阶段不测试。保持已确认的白底、墨色、淡紫装饰及字号体系，不再重做首页、品牌或工具插画。

本次核对依据：用户四张截图、`AccountView.vue`、`UserPopoverCard.vue`、`AccountManagementView.vue`、`AccountProvisioningView.vue`、`ProfileReviewView.vue`、`App.vue`、路由及相关 composable。只读策划书已阅读，冲突历史按后续已批准决定处理，不修改策划书。

| 反馈 | 已核对的现状 | 处理目标 |
| --- | --- | --- |
| 个人中心分类点击瞬间跳转、内容堆积 | 四个入口都是 `href="#..."`，成长/资料/工具/账号操作全部位于同页 | 固定个人资料头部，下方只显示当前分类内容 |
| 工作台入口缺图标 | 小窗“个人中心”有 User 图标，管理入口只有文字 | 添加现有 Element Plus 同类线性图标，尺寸和间距一致 |
| 工作台误显示返回个人中心 | `/manage` 顶部链接指向 `/account` | 工作台顶层返回首页，不表达为个人中心的下级 |
| 审核/创建按钮位置分散 | 标题与两个链接直接作为 `space-between` 的三个子项 | 工作区导航与当前任务操作分开组织 |
| 输入框聚焦时叠加异常矩形 | 全站 `[tabindex]:focus-visible` 与局部控件外框可能同时生效；旧登录/妙替等页面已有内部输入例外，管理筛选缺少 | 实际浏览器确认命中规则后解决同类根因，保留可访问的焦点提示 |

## 2. 个人中心方案

顶部保留现有封面、头像、昵称/身份、账号、等级/经验/硬币和刷新按钮。下面仍是四个分类，默认“我的成长”；不再纵向排列四大块。

| 分类 | 唯一展示的内容 | 特殊要求 |
| --- | --- | --- |
| 我的成长 | 经验进度、下级门槛/满级、当日奖励与刷新 | 复用真实成长 Store，不在切换时重复发奖励 |
| 账号资料 | 当前资料、昵称申请、头像审核说明、额度、近期申请与私有预览 | 待审与已公开值明确分开，保留上方头像提交入口 |
| 常用工具 | 当前工具入口与已有可用/筹备状态 | 继续读取 toolRegistry，不制造收藏/最近使用等未实现能力 |
| 账号管理 | 本人改密、退出及注销说明/确认 | 这是本人账号操作，不混入封禁、开户与审核；保留屋主禁注销保护 |

- 推荐使用 `/account?section=growth|profile|tools|security` 表达当前分类，正常切换进入浏览历史，刷新和前进/后退可恢复；未知参数安全回到默认分类，不额外请求后台写接口。
- 使用真实导航链接、当前项视觉标记与 `aria-current`；若实际采用 tablist，则必须同时实现其方向键/关联面板语义，不能只贴 ARIA 角色。本方案优先导航链接，避免无必要的自定义键盘逻辑。
- 同一 `/account` 内切换保持资料头部和滚动位置稳定；只调整该路由的滚动分支，不改变首页锚点、工具页及普通跨页导航。窄屏四项能换行或有明确可达入口，不依靠裁切藏起后两项。
- 兼容旧 `#my-growth`、`#profile-details-title`、`#my-tools-title`、`#account-management-title`：映射到对应分类并规范 URL，不滚动查找隐藏面板。
- 仅当前分类挂载相应业务内容，不用把所有面板隐藏但仍同时发请求的方式实现。先核对现有挂载/卸载与刷新依赖，头像提交后即使资料面板未挂载，也应给明确提示，并在进入资料分类时读取最新状态。
- 普通昵称草稿在同一账号的页内分类切换时保留，离页可清空，不持久化到浏览器；密码、再验密、临时凭据不进入 URL 或持久缓存。进行中的写操作不能因切换导致重复发起，结果未知仍沿用原核对流程；旧账号响应不能覆盖新账号。
- 首次必须改密时确保账号管理分类和改密入口可用，其他受限操作仍按既有前后端闸门禁止。退出/换号清除分类内私有内容、草稿和旧通知。
- 分类内容可以采用约 120～180ms 的轻微淡入，不动画容器高度，不堆叠旧新面板；尊重 `prefers-reduced-motion`，键盘焦点不因动画丢失。

## 3. 工作台方案

推荐桌面采用“返回首页 → 工作台标题 → 工作区导航 → 当前任务面板”，不新增侧边栏、统计卡或第二套复杂路由架构。

| 位置 | 推荐布局与行为 |
| --- | --- |
| 顶部 | 返回首页，标题按 OWNER/ADMIN 显示“屋主工作台”/“管理中心”，简短说明当前任务 |
| 主导航 | OWNER 显示“账号管理 / 资料审核”，当前项高亮；ADMIN 只显示可用的账号管理，不渲染审核或开户快捷入口 |
| 账号管理 | `/manage` 保持既有列表、筛选与分页；“创建账号”作为 OWNER 的当前任务主按钮，放在账号面板标题行右侧，与列表关联，不与大标题均匀拉开 |
| 资料审核 | `/manage/reviews` 使用同一工作区导航；页面内“待审申请 / 已发布与历史核对”分区切换，显示当前任务，保留原分页、筛选、预览和明确确认流程 |
| 创建账号 | `/manage/accounts` 是账号管理下的任务页，显示“工作台 / 账号管理 / 创建账号”上下文及回到账号列表入口；沿用原表单及单次凭据交付，不复制表单到工作台首页 |
| 小窗入口 | 屋主/管理员入口添加 `Setting` 等已存在图标库中的线性图标，实施前确认导出；保留文字、进入后关闭小窗以及精确角色限制 |

- 可提取仅含标题/导航/slot 的轻量展示组件供三个管理页使用，原路由和业务 composable 各自保留；不引入全局后台框架或通过整页 KeepAlive 缓存凭据。
- 手机下标题、导航、按钮按顺序自然换行，表单和列表占满容器，不把审核和创建拆到屏幕两端；按钮不遮挡标题或筛选。
- 离开创建结果或重置结果时继续清除明文，并提示单次交付不可找回；若增加离开确认，只保护尚未保存的明确凭据结果，不阻塞退出或账号失效清理。
- 权限、改密限制、精确目标/版本、审批原因、头像实际解码门禁、403/401 处理与响应未知核对全部复用。导航高亮或隐藏不替代后端授权。

## 4. 焦点问题的修复策略

1. 用鼠标和 Tab 在真实 Element Plus 输入框复现截图，检查 inner/wrapper/全局选择器计算样式，区分文字选区与控件聚焦轮廓，记录修复前截图。
2. 只为已证实具有可见外框焦点指示的复合控件收窄内部轮廓命中；确需修改 `App.vue` 的公共规则时说明影响，并统一核对现有局部例外，不继续给每个新页面机械补丁。
3. 检查账号筛选、昵称表单、审核原因、再验密、登录/改密、开户、妙替输入、textarea、select，以及链接、普通按钮、图标按钮、上传/文件选择入口。弹窗 Teleport 到 body 的控件也必须覆盖到。
4. 无重复直角框、无文字遮挡；键盘操作始终有清晰焦点，不能通过全局删除 outline 达到“看起来正常”。鼠标与键盘截图均纳入局部验收。
