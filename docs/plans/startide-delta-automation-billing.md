# 星潮演进计划：榜单异动标识、自动拉取显性化与 AI 费用双口径对账（dev.24）

> 所属阶段：[v1.0-dev.24.md](../dev-log/v1.0-dev.24.md) · 批准状态：**用户已全部按推荐口径批准（2026-11-26）** · 推进方式：按职责与风险拆为 3 个可独立验证、提交与回退的闭环

## 闭环 1：开源日报排行榜「突发新面孔」标识与筛选扩展

### 1. 目标与边界
- 解决 GitHub Trending Daily 每日多数为连榜“老熟人”、真正突发黑马被淹没的痛点。
- **零数据库迁移、零额外 GitHub API 调用、零 AI 费用**：不修改 `TrendReportRecord` 既有不可变归档 JSON，全部基于前 7 日已发布日报快照实时确定性计算，复用 `TrendWindowIdentity` 稳定仓库 ID 防止改名误判。

### 2. 批准设计口径
- **4 类榜上身份信号**：
  - `NEW`（**新上榜**，高亮主标）：前 7 天（含上一已发布日）从未在榜，今日首次出现；
  - `NEW_TOP`（**空降前 5**，强提醒）：首次上榜且直接进入 Top 5；
  - `RETURNING`（**重回榜单**，温和标）：上一已发布日不在榜，但前 7 天内曾上过榜；
  - `STREAK`（**连榜 N 天 + 排名升降**，低对比度降噪标）：连续在榜 ≥ 2 天展示 `连榜 N 天`；上一已发布日就在榜且排名上升 ≥ 3 位附轻量 `↑N`。
- **前端体验扩展**：
  - 日报抬头补充 `今日新上榜 X 个` 统计摘要，工具栏新增一键切换 **「只看新面孔 (X)」** 过滤按钮（与语言、技术分类筛选自然组合，保留原始官方排名）；
  - 榜单底部新增默认折叠的 **「昨日退榜速览」** 条目区（仅展示上一已发布日在榜、今日退榜的项目，不占主版面）。
- **防误判护栏**：无前序历史日报（如首期或前 7 天无已发布日报）时优雅隐藏新面孔徽标，绝不误标全榜 25 项为新上榜。

### 3. 验收标准
- 后端纯计算器 `TrendPresenceCalculator` 表驱动单测覆盖首期、正常连榜、空降前 5、重回榜单、缺采日、仓库改名（同 `repositoryId`）及昨日退榜列表；
- 前端单测 + `npm run build` + 桌面/手机断点检查，确保筛选叠加、焦点与换行零异常。

## 闭环 2：显性开放每日自动拉取日报 + 7 日风口简报顺路自动生成

### 1. 目标与边界
- 既有后端定时调度（`TrendDailyScheduler`、`TrendJobStore.scheduleDue`）与 GitHub Actions 唤醒（`.github/workflows/trend-wake.yml`）底层已就绪但全藏在环境变量后，屋主在发布台不可见；同时 7 日风口简报单次空闲时段实扣仅约 ¥0.007（月约 ¥0.20），值得自动刷新以消除读者页空白/过期提示。
- 本闭环仅做代码能力、显性状态面板与云端启用/回退运维清单；**实际 Render / GitHub Variables / TiDB `015` 迁移仍须用户另行明确授权执行**。

### 2. 批准设计口径
- **发布台显性状态面板**：
  - 后端新增屋主只读查询接口（遵循 `OWNER` 权限与 `Cache-Control: no-store`），返回：自动日报开关状态、计划执行时间（北京时间 `dailyTime` + 补偿延迟）、自动简报开关状态、今日自动受理状态（等待窗口 / 已自动发布 / 当日已有跳过 / 失败待补偿等）及最近 5 条任务记录（区分 `SCHEDULED` 定时自动与 `MANUAL` 屋主手动）。
  - 前端 `TrendOwnerView.vue` 新增精简的「每日自动采集状态」卡片，一目了然展示上述状态与记录。
- **7 日风口简报自动串联（独立开关 + 故障隔离）**：
  - 新增独立配置开关 `polyhouse.trend.briefing.auto-enabled`（环境变量 `POLYHOUSE_TREND_BRIEFING_AUTO_ENABLED`，默认 `false`）。
  - 仅在每日自动日报发布成功且满足简报样本硬门槛（`coveredDays >= 3 && radar3ReadyCount >= 5`）时，在 `TrendJobRunner` 结束前以独立 `try/catch` 触发一次系统简报生成：
    - 简报任何异常/预算不足均仅记安全日志，**绝不影响已发布日报的任务成功状态**；
    - 复用现有 `TrendBriefingLedger` 同指纹幂等防重与 10 元共享月预算红线。

### 3. 验收标准
- 后端单测与隔离验证覆盖：自动简报开关关闭不触发、开启且日报成功后触发、简报失败不影响日报发布、同指纹零费用跳过、发布台只读接口 401/403/`no-store` 负向用例；
- 前端发布台组件单测与构建通过；运维文档补充 Render 与 GitHub Variables 一键开启/回退清单。

## 闭环 3：AI 费用双口径对账（保守安全闸门 + 预计平台实扣 + Token 汇总）

### 1. 目标与边界
- 核查确认当前应用账本故意按 DeepSeek `deepseek-flash` 高峰未命中全价（2 元 / 8 元每百万 tokens）记账，未扣除空闲时段 5 折优惠与 `prompt_cache_hit_tokens`（0.02～0.04 元/百万）缓存优惠，导致账本普遍比平台实扣高出 50%～70%。
- **安全底线不变**：10 元月预算硬闸门继续严格按原保守高峰口径执行，绝不因优惠放松预算上限导致超支。

### 2. 批准设计口径
- **采集真实缓存命中字段**：
  - `TrendInsightCodec.envelope` 与 `TrendBriefingCodec.envelope` 兼容解析可选字段 `usage.prompt_cache_hit_tokens` 与 `usage.prompt_cache_miss_tokens`（缺省或旧桩测回退 `hit=0, miss=prompt_tokens`）。
  - 新增增量迁移 SQL（如 `017_trend_ai_cache_tokens.sql`，不改旧迁移）在请求明细表记录缓存命中/未命中 token 与参考实扣估算微元，保持既有行兼容。
- **双口径展示与 Token 级对账**：
  - `TrendFeeVO` 与前端 `TrendFeeLedger.vue` 并列展示：
    1. **安全预算已用**（原保守高峰口径，用于控制 10 元硬闸门）；
    2. **预计平台实扣**（按真实缓存命中单价 + 北京时间工作日高峰/非高峰时段估算，显式注明不含法定调休节假日）；
    3. **本月 Token 汇总明细**（调用次数、输入总计、缓存命中数与命中率、输出总计），便于屋主 5 秒对照 DeepSeek 控制台用量明细核账（并提示区分多环境是否共用同一 API Key）。

### 3. 验收标准
- 后端表驱动单测覆盖缓存命中解析（含缺失兼容与越界拦截）、高峰/空闲时段参考实扣计算、保守闸门不受优惠影响，以及新增迁移的随机隔离库集成测试与逆序回退检查；
- 前端费用面板兼容解码测试与构建通过。
