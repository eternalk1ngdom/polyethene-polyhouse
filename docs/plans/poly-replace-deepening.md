## 0. 本轮批准范围与验收边界

2026-11-01：用户认可“先完成 R1，独立验证和提交后再评估 R2”的推进方式，并明确要求按此执行。R1 只做模型、纯校验、本地存储层与测试；不新增 UI、不接入页面、不自动保存草稿、不提供导入导出交互，也不改内核、Worker、后端、依赖或数据库。

- 介质为 `localStorage`，词库属于同一浏览器来源与配置文件，不随账号；本轮不接入认证或自动清理逻辑。
- `utils/ruleLibrary.ts` 只做固定字段模型、校验与 JSON 编解码；`stores/ruleLibraryStorage.ts` 管理副作用和会话内状态。R2 再接入响应式界面，不为未出现的 UI 提前建立全局 store。
- v1 格式：`{ version: 1, sets: [{ id, name, rules, createdAt, updatedAt }] }`。ID 为 1～64 位 ASCII 字母/数字/下划线/连字符、首位字母或数字；时间为非负、有效日期范围内的 UTC 毫秒整数，更新时间不早于创建时间。
- 最多 30 组，每组 1～20 条。名称去首尾空白后为 1～32 个 UTF-16 代码单元，按 NFC 与小写形式判重；查找非空，查找与替换各不超过 200 代码单元，字面空白保留、同组查找精确判重，拒绝孤立代理项。空库合法，删除规则的空替换合法。
- 原始存储和规范化序列化均不超过 256 KiB，按 UTF-8 实际字节计算；组数与体积是双重上限，不保证 30 组最长中文规则都能存满。拒绝未知版本、未知字段与非法结构，普通字符串中的 `constructor` 等单词不属于危险对象键。
- 载入损坏/未知版本数据时保留原始存储，未成功读取前不写入；不静默重置。保存失败仍保留有效内存候选，并返回机器可判定状态与脱敏提示；不能以“内存已更新”冒充持久化成功。重载需明确舍弃未保存候选，重载失败仍保留候选。
- 所有本模块写入使用同名 Web Locks 排他锁，在锁内比较读取时的原始值并一次写入；陈旧页面拒绝覆盖，保留候选供后续核对。锁缺失/被拒绝时仅保留会话内修改；不声称普通读后写具有事务性，也不承诺阻止不遵守协议的外部脚本或开发者工具改写。依据：[Web Locks](https://developer.mozilla.org/en-US/docs/Web/API/Web_Locks_API)。
- R1 验收：有效数据往返与内核兼容，结构/重名/Unicode/容量边界，坏数据保留，读写故障与重试，两个实例并发保存，等待锁时的快照与重复操作隔离，以及浏览器适配接口。执行专项/全量前端测试、静态检查和构建；无后端改动不运行 Maven，无界面改动不冒充已做浏览器交互验收。R2 接入时仍须实际验收刷新、双标签页与键盘/布局。

## 3. 交互方案

### 3.1 词库面板

在“2. 设置替换规则”区域顶部增加词库操作，保留现有双栏基线（700px 及以下单栏），具体布局由 R2 实施前留基线再评估：

- **保存当前规则**：输入名称后保存为一组；同名（不区分大小写）时提示覆盖或另存，不静默覆盖。
- **载入**：选择一组后替换当前规则，并沿用既有 `invalidate()` 清空旧结果，避免下载包与界面规则不一致。
- **重命名 / 删除 / 复制**：删除需二次确认并显示该组规则条数；复制自动加“副本”后缀。
- **空词库状态**：显示一句说明与“把当前规则存为词库”的入口，不展示空列表骨架。

载入属于本地操作，不触发网络请求，也不改变“开始替换”的显式触发方式。

### 3.2 草稿恢复

- R3 已批准，以第 0.2 节为准：默认关闭、主动开启并记住选择，400ms 防抖；清空须删除本页旧草稿，未填写完整的规则仍可恢复。离页补存仍不承诺异常关闭时零丢失。
- 进入页面时有历史则提示选择恢复，未决时暂停自动写；“保留当前编辑继续”不删除历史，删除历史和清空本页另行确认。仅以 sessionStorage 页面 ID 优先定位刷新前来源，清空后不再自动提示其他历史，仍可手动选择。
- 恢复通过父页面原规则变更流程清除旧结果、保留文件；载入词库也沿用明确覆盖确认，待决旧稿不会被自动覆盖。R5 按第 0.6 节统一来源选择：使用链接/暂不载入保留旧历史，恢复草稿仍走原路径。

### 3.3 导入与导出

- 导出为单个 JSON 文件，文件名带日期（如 `妙替词库-20261031.json`），内容是完整词库而非当前规则。
- 导入仅 **替换全部**：读取前检查大小，校验备份并成功重读本机后展示确认；最终整库校验通过才一次写入。保留备份元数据与顺序，不合并、不自动载入规则或执行替换；空备份特别提示清空。
- 解析只接受 JSON 数据，不执行任何脚本；拒绝 `__proto__`、`prototype`、`constructor` 等键，与 `validateBatch` 现有的原型污染防护保持一致。

### 3.4 链接分享

R5 已按第 0.6 节交付：分享当前完整规则，接收先预览、统一决定链接或草稿来源，再自动清理片段；异常/复制与清理失败分别提示。正式词库保存仍使用既有入口，文件/自动执行边界保持不变。批准范围和验收以第 0.6 节为准，事实与证据见 dev.10，不保留旧“直接载入/手动清除”候选作为并行约定。

### 3.5 命中统计与预览定位

- R6 第一闭环按第 0.7 节已完成：逐条显示当前预览文件和整批实际执行次数，原规则顺序、零值和全文统计保持明确，证据见 dev.10。
- 高亮/定位仍为候选：点击定位到预览内该规则的第一处执行并短暂强调；按片段渲染文字而非 `v-html`，不把文件文本当网页代码。
- 后续实施前确定删除的零宽标记、预览窗口外/超位置上限的提示和定位交互；当前只有计数，没有位置记录或高亮骨架，仍保留只读 textarea。

### 3.6 文件夹内文件手动筛选

- 采用第 0.5 节用户决定：默认全部参与，由用户选择哪些文件跳过；不按目录名、扩展名等自动排除，不设置原目录黑名单或“包含被排除目录”开关。
- 选择文件夹后先保留候选文件引用，按相对路径显示清单，用户可调整参与状态；建议以“勾选 = 参与处理”表达，暂不扩展复杂目录管理。具体控件和候选清单规模在实施前明确。
- 不因候选数超过 20 就立即清空拒绝：先允许用户缩小选择，再对参与文件调用现有完整校验。显示“共 N 个，参与 M 个，跳过 K 个”；参与数为 0、超过 20 或违反单文件/总大小等限制时明确提示并阻止处理，清单保留以便调整。
- 保留原候选，跳过后可以重新选回；参与集合变化沿用原失效流程，清除旧结果/下载并停止旧任务，不自动执行替换。只读取参与文件的正文，ZIP 只包含参与文件及其相对路径，不改动磁盘原件，空文件夹边界保持原实现。
- 不默认识别或排除剩余二进制文件；原文本解码/整批失败保护继续有效。文件夹枚举仍由浏览器先完成，大目录可能耗时；候选列表性能与展示上限须另定，不把此功能宣称为大型工程或无限文件处理能力。
- 20 文件、2 MiB、5 MiB 限额针对实际处理集合保持不变，提高处理容量不在本轮方向确认内。

## 4. 数据与存储设计

| 项 | 建议值 | 理由 |
| --- | --- | --- |
| 存储介质 | `localStorage` | 纯文本、总量小，同步 API 失败路径简单；IndexedDB 的事务与版本升级成本换不来实际收益。若批准时预期词库规模远超下表，再改 IndexedDB |
| 词库键 | `polyhouse:replace:library:v1` | 沿用 `polyhouse_`/`polyhouse:` 命名习惯，带版本便于将来迁移 |
| 草稿键 | `polyhouse:replace:draft:v1` | 与词库分离，忽略草稿不影响词库 |
| 结构 | `{ version: 1, sets: [{ id, name, rules, createdAt, updatedAt }] }` | 与导出格式同构，减少两套校验 |
| 容量上限 | 30 组；每组 ≤20 条、每条 ≤200 字符；名称 1～32 字符；整库序列化 ≤256 KiB | 与内核上限一致，避免词库能存但载入即失败 |
| 超限处理 | 拒绝保存并提示删除旧组或导出后清理 | 不静默截断规则，避免用户以为已保存 |
| 存储不可用 | 降级为“仅本次会话可用”，提示后继续允许替换 | 隐私模式/禁用存储不能阻塞主流程 |
| 写入失败 | 捕获配额异常，保留内存状态并提示未保存 | 与现有“网络失败不冒充成功”的反馈原则一致 |

隐私与边界：

- 词库与本机浏览器绑定，**不随账号**：退出登录不清除，换账号仍可见。这是本机设备级数据的合理语义，但必须在界面上写明“本机词库”，并提供 **清除本机词库** 入口，避免共用电脑时误以为属于账号。
- 词表可能是敏感内容（如脱敏词表），因此：默认不上传、不写入账号缓存、不进入任何接口；导出必须用户主动点击；页面上明确“仅保存在本机，清除浏览器数据会丢失，建议定期导出”。
- 不加密。本机明文加密在没有密钥管理的前提下只会制造虚假安全感；用“只存本机 + 可导出 + 可清除”来控制风险，并在计划中如实记录这一取舍。

## 5. 算法与协议改动

- R6 统计已实现：`ReplaceResult`/`ReplacedFile`/`FileSummary` 增加 `ruleCounts: number[]`，Worker 显式投影，保留 `text` 与 `count` 语义；完整对象断言、直接匹配对照、批量/Worker/页面及基准同步验证。下列位置/渲染设计仍为后续候选。
- 命中位置在拼装输出时同步累计（扫描阶段得到的是原文坐标，替换后需要输出坐标），只保留落在预览窗口内、且数量上限（建议 500 处）以内的位置；超出时只给计数。这样可以避免密集命中把 Worker 消息体撑大。
- 后续 `FileSummary` 才考虑增加 `previewHits: { start, end, ruleIndex }[]`；当前只有 `ruleCounts`。`WorkerReply`、`BatchDownload` 外层字段保留，未来嵌套摘要、Worker 投影及相关测试仍须同步。
- 预览仍是前 10000 字符（`polyReplaceBatch.ts:126`），高亮坐标相对预览字符串，不相对完整结果。
- 内核保持纯函数：不引入 DOM、不引入 Vue 响应式、不读写存储；存储与渲染都在页面/store 层完成。
- R6 高亮闭环前仍须另定删除替换的零宽定位、预览窗口外/超过 500 处的提示，不承诺每条规则都能定位；当前/整批计数已按第 0.7 节明确。位置上限仍是建议，不作为已实施能力。
