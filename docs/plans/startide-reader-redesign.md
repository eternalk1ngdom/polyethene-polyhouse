# 星潮改版计划 · 日报目录、项目详情与星潮发布台

2026-11-18 · v1.0-dev.15。**2026-11-19 进度：第 1～3 步已完成本地验收，下一步为第 4 步联调与收口。** 发布入口与标题已统一命名。[本轮验证](../dev-log/v1.0-dev.15.md) 用户确定沿用首页「纸船逐星」的画风，先打磨读者页面，再重设屋主发布界面。按以下顺序实施，具体构图和配色可随页面任务调整。实施基线为本机 `codex/github-tech-radar` 的 `5240f6e`。[首版功能与接口](trend-frontend-design.md) · [业务范围](github-tech-radar.md) · [前端体验参考](../design/frontend-experience.md)

## 一、读者要完成的两件事

现在点仓库名会离开本站，中文长文藏在同一行下的折叠项里。对截图中这期 20 个项目，读者通常先扫名称、用途与涨星，再决定哪一条值得细读。建议把这两个动作各做成一个页面。代价是深入阅读多一次点击，因此目录必须有足够内容供人判断，读完也须能回到刚才那一行。

| 页面 | 最先看到 | 主要操作 |
| --- | --- | --- |
| 星潮日报 `/trend` | 正在读哪一期、上榜项目、每项是做什么的 | 切日期、筛语言、打开项目 |
| 项目详情 `/trend/:date/:owner/:repo` | 哪一期的哪个项目、它做什么、为何值得看 | 深读解读、去 GitHub、回到原榜单 |
| 星潮发布台 `/manage/trend` | 今天能否发起更新、已跟踪任务进展与结果 | 屋主更新日报、续查任务、查看费用 |

### 三页怎样既统一又有变化

沿用「纸船逐星」的浅蓝纸底、靛青字色、标题字形和焦点样式。目录可以像彩色日报封面，详情用舒展的正文和页边注，发布台用紧凑的任务面板。亮金、湖蓝、薄荷绿、珊瑚橙都可提高饱和度，集中用在读者此刻需要注意的位置，如涨星列、已选语言、当前发布阶段。长文保留清晰的深浅对比，状态同时用短标签或形状表达。

能让人直接筛选、核对或展开依据时，优先把说明做成小控件。例如语言选项可显示当期数量，点选即筛、点「全部」即恢复；详情可用「解读依据」展开模型、资料版本与生成时间，沿用旧解读的标记和原时间仍放在摘要旁；发布台可用带阶段名的步骤条显示当前进展，点开已有阶段可查接口实际返回的信息。按内容选用这些做法。项目用途、失败原因和可能产生费用的提示仍直接可读。

### 可借鉴的两处设计

- GitHub Trending 将仓库、简介、语言和本期涨星放在同一条目。星潮借用这种读数顺序，同时保留来源名次，筛选后仍能与 GitHub 对照。[GitHub Trending](https://github.com/trending)
- Product Hunt 的每日榜把名称、一句用途和数字放得很近，名称可进入该产品。星潮借用这条发现路径；这里的星标表示 GitHub 已采集的数据，交互入口是项目名。[Product Hunt](https://www.producthunt.com/)

## 二、日报目录如何扫读

1. **短报头。** 将「星潮 StarTide」排在[星月潮汐插画](../../polyhouse-web/src/assets/startide-tide-atlas.webp)左侧天空内，桌面并排、窄屏上下排。插画以底边为准等比取景，保留月牙、星群及海平线以下多层潮水。封面下方放筛选控件，在「开源项目日报」标题下集中展示所读期号、本期项目总数和采集时间。以常见笔记本首屏能看到前两条为设计目标。
2. **期次与筛选。** 报头下的一行放「日报日期」「编程语言」，旁边显示采集时间（北京时间）和「GitHub 日榜来源」。复用已有日期游标读取更早期次。筛选只作用于当期，如「Python · 5 / 20 个」，一击恢复全部。同一期不再加第二套搜索、分页或分类导航。
3. **紧凑的单列排行。** 桌面从左到右为原名次、项目与摘要、本期涨星。项目名最醒目，所属组织弱化但保留；下方最多两行用途，优先显示标明来源的一句话 AI 解读，缺失时用 GitHub 原简介，再缺时保留可进入的名称。语言用文字加小色点。陈旧解读在摘要旁标「沿用旧解读」。手机把语言和涨星放入次行，仓库长名自然换行。完整简介可在详情阅读。
4. **让图标承担重复信息。** 涨星列共用一次「本期新增」说明，行内以星形图标和 `+2,322` 对齐；手机保留可见的指标说明。屏幕阅读器读作「本期新增 2,322 个星标」。零显示 `+0`，来源缺数用长横线配「数据未知」。星形为统计符号，聚焦和悬停反馈给真正可点的项目链接，避免产生能点赞或收藏的错觉。
5. **保住阅读上下文。** 保留 `/trend?date=YYYY-MM-DD`，语言进入查询参数。读者在最新一期选中一条时，用已返回的北京时间期号生成详情地址。站内返回和浏览器后退均恢复原筛选、滚动及项目名焦点。涉及时跨午夜或列表重新加载，先恢复原期，再等待条目挂载定位；条目已移除时回到该期列表标题。直接打开分享链接也能返回对应日报。

## 三、项目详情如何深读

- **页首回答“它是什么”。** 返回当期榜单 → 期号与原名次 → 仓库全名 → 一句话定义或 GitHub 简介。标题旁显式提供「在 GitHub 查看 ↗」。站内项目名进入详情，只有标出 GitHub 的链接才跳往站外。
- **正文回答“是否适合我”。** 依次为解决的问题、技术亮点、同类差异；随后分别呈现「项目文档明确的限制」与「AI 推测的风险」。AI 段标注模型、生成时间及复用情况。已有内容直接排版，缺少的可选章节收起；没有 AI 时，原始简介、仓库资料和来源仍是一张完整可读的页面。
- **数据作为旁注。** 宽屏用正文加窄资料栏，窄屏将资料排在摘要后。展示本期新增、总星标、Fork、主语言、许可证、归档状态与采集时间，GitHub 原始描述保留原文。资料未知与实际为零分开。旧解读展示原生成时间，不能让本期采集时间看起来像本期分析时间。
- **路由与数据。** Vue Router 继续使用现有 hash 模式。日期和仓库的两个路径段分别校验，按已验证的 `fullName` 匹配；排名随发布变化，`repositoryId` 可能为空。公开接口按日期给出当前已发布版本，不能按版本号读取旧版。模块内复用当前这份已加载日报；新标签页或直接刷新时调用一次现有日报查询。同日重发后若仓库仍在则展示新快照，若已移出则说明「该项目未收录在这期当前版本」并链接当期目录。读取或重试都只走公开 GET，无需请求 GitHub、DeepSeek 或新增后端接口。

## 四、星潮发布台如何办事

选用 **「星潮发布台」**。它既涵盖发起更新，也涵盖跟踪任务和查看当月费用。星潮入口、页面标题、浏览器标题统一改名；个人菜单中的「屋主工作台」继续指向原有账号管理区。公开页将发布入口放在次要位置，仅对符合现有条件的屋主显示。

| 区域 | 布局及行为 |
| --- | --- |
| 日报更新 | 页首显示「返回星潮日报」，主操作写「更新本期日报」。即使从历史期进入，也明确更新针对当前期。按钮旁说明启用 AI 时可能产生费用。身份核对中、需改初始密码、会话失效或权限不足时，沿用现有身份处理。 |
| 本次任务 | 受理后展示来源、受理时间与真实阶段「排队 → 采集 → 解读（按需）→ 发布」。用文字和形状区分状态。已发布、部分解读可用、失败、中断各有结果说明，已有发布结果给出「阅读最新日报」。暂无已知编号时写「暂无本页跟踪的任务」。 |
| 断开后继续 | 沿用 `useTrendOwner`。连点、提交响应丢失和刷新均复用同一次意图或已知任务号；活动任务按已有节奏查询，遵守 `Retry-After`，离页或换账号停止。只展示接口可证实的进展，不能从经过的秒数估算百分比。 |
| 本月 AI 费用 | 放在任务结果之后。并列显示已入账、在途占用、剩余、月上限，注明应用估算与人民币单位。暂停原因提示及待核对明细可展开、翻页，保留微元精度。费用只读，待核对操作维持首版边界。 |

## 五、实施顺序与每步完成标志

| 顺序 | 交付 | 完成标志 |
| --- | --- | --- |
| 1 · 接通目录与详情 | 在星潮模块内拆开列表项和详情正文，复用 `api/trend.ts` 的校验，接通新路由。保留旧日报、历史期及发布台地址。 | 先让一个真实已发布项目走通「点开 → 刷新详情 → 返回同一期同一条」。覆盖仓库 ID 缺失、同日名次变化、项目移出和非法日期。此步完成后原来能读到的信息仍有入口。 |
| 2 · 打磨公开阅读 | 按第二、三节完成桌面与手机排版，处理图标语义、来源标记、筛选恢复与阅读焦点。 | 使用同一期真实内容对照改版前后截图。用键盘从筛选后的列表进入项目再返回，用手机直开分享链接。两条路径都能定位到正确期号和仓库。 |
| 3 · 重设星潮发布台 | 统一星潮内命名，重排任务、结果与费用，复用现有权限、轮询和防重逻辑。 | 屋主可辨别下一步动作，非屋主直达管理地址走原权限提示。用隔离数据核对提交响应丢失、429、部分发布、失败和费用暂停。验收不依赖付费重发。 |
| 4 · 联调与收口 | 用本机正常启动方式串起首页卡面、日报、详情、发布台及返回路径。 | 分阶段运行前端构建、静态检查及受影响测试。在 320、375、桌面宽度以及实际换列断点两侧，用鼠标、Tab、回车和浏览器前进后退核对。分别记录实测、夹具覆盖和未验边界。 |

每步都保留可运行的入口，验证通过后独立本地提交。日期请求和日报请求可分别失败，保留各自的重试；快速切期须丢弃迟到结果。公开页面验收还要覆盖暂无日报、筛选无结果、无解读、沿用旧解读、长仓库名、200% 缩放及减少动态效果。实测所选微型控件能用触屏和键盘完成同一操作，当前选项、展开状态和任务阶段可被读屏识别。鲜艳色块上的文字须检查对比度。装饰插画使用空替代文本，图标链接有可读名称，触屏无须悬停即可理解和操作。

**本阶段范围**为星潮两张公开阅读页与专属发布页。沿用现有首页卡面、顶栏、依赖版本、开发启动方式、API 和权限。跨期曲线、全库搜索、收藏、发布历史、费用写操作需要各自的数据或产品决定。远端提交、PR、合并和部署沿用项目授权流程。
