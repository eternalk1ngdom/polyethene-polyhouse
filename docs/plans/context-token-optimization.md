# 上下文与 Token 降本瘦身专项计划（dev.23）

> 所属阶段：[v1.0-dev.23.md](../dev-log/v1.0-dev.23.md) · 基线：`dev` @ `fb7fd55` · 性质：工程效能与协作降本专项（零业务代码、零 UI 改动、零依赖升级）

## 一、背景与量化基线

每次开启新会话或执行常规开发闭环时，固定上下文与工具输出会持续消耗 Token 并推高轮数：

| 损耗来源 | 优化前基线 | 问题诊断 | 优化目标 |
| --- | --- | --- | --- |
| `AGENTS.md`（每轮系统提示常驻） | 77 行 / 7,106 字符 / 16.6 KB | 条款间存在重复表述（如验证、发布授权、日志说明多处复述），文字偏长 | 零规则降级下压至 **≤ 5,200 字符**（降幅 ~27%–32%） |
| `DEV_LOG.md`（每会话必读入口） | 60 行 / 4,451 字符 / 7.2 KB | 严重超出 `AGENTS.md` 规定的 2,500 字符上限；顶部 bullet 与底部历史索引表大面积重复 | 压回 **≤ 2,400 字符 / 40～55 行**（降幅 ~48%–55%） |
| 前端/后端普通测试输出 | `npm test` 每次打印 ~500+ 行通过用例名；`Test-Project.ps1` 全量直出 | 通过时冗余日志淹没上下文；失败时难以一眼定位报错 | 新增静默验收入口：**通过仅输出 1 行摘要，失败完整展开原始错误** |
| 日常文档同步轮数 | 中间提交频繁同步 `DEV_LOG.md` + 阶段日志 + 计划索引，常多开 1～2 轮纯补文档回合 | 事实源分散导致重复编辑与额外提交 | 确立 **SSOT 分层同步** + 代码验证同轮并行补日志，消除日常冗余轮次 |

## 二、实施范围与边界

### 1. 阶段切分（已完成）
- 按 `AGENTS.md` 切分规则冻结 [v1.0-dev.22.md](../dev-log/v1.0-dev.22.md)（保留全部历史事实，顶部改为「阶段摘要（已冻结）」），新建 [v1.0-dev.23.md](../dev-log/v1.0-dev.23.md)。

### 2. 双文档零降级瘦身
- **`DEV_LOG.md`**：顶部只保留「当前状态与未决边界」「长期不可违背约束（正式屋主、依赖冻结、授权红线）」「核心入口链接」；已收口历史阶段全部收归精简的「历史索引」表，彻底消除顶部与表格双份复述，不丢失任何阶段链接与关键事实。
- **`AGENTS.md`**：合并重复表述、压缩冗余修饰语，**100% 保留**全部 10 条铁律、按影响验证表、3 条测试编写红线、汇报通俗化与四段式要求、Git/PR/安全授权红线及最小影响判断，并将「测试静默输出入口」与「SSOT 降频文档同步」合并入原条款。

### 3. 测试静默输出脚本（Silent-on-Pass / Verbose-on-Fail）
- **`polyhouse-web/scripts/run-tests-quiet.mjs`**（并在 `polyhouse-web/package.json` 追加 `"test:quiet"` 脚本，不触碰任何依赖版本）：
  - 调用 `node --test` 运行全部或指定路径测试（支持传入测试文件/通配路径参数）。
  - 全部通过时：仅打印 1 行精简汇总（如 `[PASS] 前端测试：474 通过 / 0 失败 / 0 跳过 (1.4s)`）。
  - 任一失败时：自动打印失败用例详情与错误堆栈，并以原始非零退出码返回。
- **`polyhouse/scripts/Test-Quiet.ps1`**：
  - 支持 `-Scope All | Backend | Frontend | BackendCompile | BackendTest | FrontendLint | FrontendTest | FrontendBuild` 与 `-Filter`（后端 `-Dtest=...` 或前端测试路径）。
  - 默认静默模式：各阶段输出重定向捕获，通过仅打印单行 `[PASS]` + 耗时与计数；任一阶段失败立即输出完整捕获日志并抛出非零错误码。
  - 同时为 `polyhouse/scripts/Test-Project.ps1` 增加可选 `-Quiet` 开关（默认保持原有详尽输出，零破坏既有调用方）。
- 同步更新 [docs/operations/verification.md](../operations/verification.md) 说明静默验收入口与适用场景。

### 4. 减少日常文档同步轮数（SSOT 降频机制）
- **单事实源分层**：
  - 过程实施事实、命令与验收证据 → 只写当前阶段日志 `docs/dev-log/v1.0-dev.<N>.md`。
  - 根 `DEV_LOG.md` → 仅在里程碑/批次收口、分支合入或阶段切分时更新，不再为单次中间提交同步。
  - `docs/plans/README.md` → 仅在计划立项、批准变更或整项收口时更新。
- **同轮并行收口**：代码验证通过后，在同一回复轮次内并行完成日志更新，与代码/测试打包在同一闭环提交中，减少“先交代码、再开一轮补文档”的往返。

## 三、验收标准

1. **量化达标**：`DEV_LOG.md` ≤ 2,500 字符；`AGENTS.md` 较基线明显瘦身（≤ 5,200 字符）且逐条核对无规则降级或遗漏。
2. **脚本实测与红绿复核**：
   - 前端 `npm run test:quiet` 全量通过时输出 ≤ 3 行，定向单测与故意触发失败的红绿复核能完整展开报错并以非零退出码终止。
   - `.\polyhouse\scripts\Test-Quiet.ps1` 分别验证 `-Scope Frontend` 与 `-Scope BackendCompile` / 定向 `-Scope BackendTest -Filter ...` 正常通过，且在传入无效/失败用例时能完整输出失败日志并返回非零退出码。
   - `.\polyhouse\scripts\Test-Project.ps1` 语法检查通过，原有默认参数调用兼容。
3. **一致性核对**：全部新增/改动文档相对链接有效，`DEV_LOG.md`、`v1.0-dev.22.md`、`v1.0-dev.23.md`、`docs/plans/README.md`、`docs/operations/verification.md` 状态一致。
