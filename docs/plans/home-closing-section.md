# 首页工具列表之后，留什么？

2026-11-23 · 用户预览方案 B 后认为独立说明区较突兀、用处有限，最终选定方案 A。已在 `feat/home-closing-section` 实施，分支基线为 `dev` 的 `5888dc7`。下文保留选型时的依据及备选方案。

## 一、取舍

**建议撤掉“去我的个人空间”大按钮，保留一个明显更短的收尾区，首选方案 B。** 浏览者已经看完工具的名称、能力和入口，此时还有一个与选择工具直接相关的问题值得回答：把自己的照片或文本交给这个网页后，文件会去哪儿，原件会怎样？两句话就能答清。个人资料和成长记录则有自己的固定入口。

直接删掉整块也是合理选项。如果看过两种版本的访客在理解文件处理方式上没有可辨别的收益，建议采用更短的 A。这里没有点击数据或访谈结果可以证明用户一定需要这个模块。

## 二、现有页面与使用路径

| 位置 | 现在能做什么 | 对方案的影响 |
| --- | --- | --- |
| 顶部账号入口 | 游客可原地登录；已登录者可从头像小窗进入个人空间 | 两种状态的入口和目的都明确，移动端也要验一次 |
| 三张工具卡 | 星潮读日报、妙替替换文本、妙压压缩图片；卡片已经有各自的行动按钮 | 列表末尾无需把三个工具再介绍一遍 |
| 截图中的首页末段 | 英文眉题、中文标题、两行品牌介绍、账号按钮和英文签名依次居中 | 按钮是全段唯一可操作元素，容易让初访者把登录理解为使用工具的下一步 |
| 紧接着的全站页脚 | “个人空间”直达同一地址；桌面重复上方的英文眉题，手机保留空间链接 | 删除上方按钮后，滚到页末的人仍能就近找到账号 |

对本机现有预览实测，1440 CSS 像素宽时，浅色面板宽 1320、高 394，距页脚 72；375 宽时面板宽 335、高 413，距页脚 44。两个尺寸上，面板按钮与可见的页脚链接都指向 `#/account`。手机端这个模块比桌面端还高，优先回收纵向空间比增加装饰更有价值。

现行首页设计包含“工具画廊 → 品牌介绍”。路由还支持直接定位 `#about`。推荐方案沿用这个段落和锚点，换成能体现产品做事方式的内容；若选整段删除，需要同步调整设计记录并保留旧链接的合理落点。[首页实现](../../polyhouse-web/src/views/HomeView.vue) · [全站页脚](../../polyhouse-web/src/App.vue) · [顶部导航](../../polyhouse-web/src/components/TopNavBar.vue) · [个人小窗](../../polyhouse-web/src/components/UserPopoverCard.vue) · [路由](../../polyhouse-web/src/router/index.ts) · [视觉基线](../design/frontend-v2.md)

## 三、三个同类首页把列表末端用来做什么

| 站点 | 工具目录之后实际放了什么 | 对聚妙屋的启发 |
| --- | --- | --- |
| PDF24 | 在目录后的说明区交代文件如何传输、在线处理在哪里发生，以及本地桌面版适合谁。[PDF24 Tools 首页](https://tools.pdf24.org/en/) | 文件去向是一个适合在选工具时回答的问题。聚妙屋可用自己的实际行为给出更短的答案。 |
| iLovePDF | 在工具后提供组合工作流，以及按离线桌面、移动设备、企业使用划分的入口。[iLovePDF 首页](https://www.ilovepdf.com/) | 第二个入口值得出现的前提是它能完成不同任务。聚妙屋目前没有与三张工具卡对应的跨工具工作流，重复账号入口提供的增量很小。 |
| TinyWow | 大目录之后精选部分工具，再解释付费支持权益；页脚用短句交代文件的保留时限。[TinyWow 首页](https://tinywow.com/) | 工具多时，二次精选有助于缩小范围。聚妙屋目前只有三张卡，更适合借鉴后一种做法，用一条具体说明消除顾虑。 |

这些是页面上可以观察到的安排。各站点的工具规模、文件处理方式和商业目标不同。没有公开转化数据支持直接照搬其中任一布局。

## 四、三个可选方向

| 方案 | 访客实际看到什么 | 适用条件与代价 |
| --- | --- | --- |
| A · 直接结束 | 最后一张工具卡之后进入全站页脚 | 页面最短。适合以最快选工具为唯一目标，或实测用户已充分理解文件处理方式。会失去首页原有品牌介绍；实施时应让旧的首页 `#about` 定位到实际页末内容。 |
| **B · 一张简短的用前说明（首选）** | 一句标题、两句正文、一处很小的纸角 | 让新访客在选择本地工具前知道文件去向，亦保留纸质插画的余味。能否让用户更安心，需要通过阅读任务确认。 |
| C · 保留品牌落款 | 留下原句“把时间，留给你喜欢的事。”作为简短落款，去掉按钮和上下两句英文 | 若首页更重视品牌印象，这是成本最低的视觉改法，且同时适合星潮读者与工具用户。代价是访客几乎得不到新的使用信息。 |

## 五、推荐方案的文案和构图

预览时先使用下面这一组完整文案。全段无按钮，页脚继续提供“个人空间”。

> **原文件会留在你手里。**
>
> 用妙替改文本、用妙压压图片，文件都在你的浏览器里处理。下载的是处理好的副本，原文件保持原样。

这段文字明确点名妙替和妙压。两张工具卡已有“本地运行”标签，收尾区补上的是“文件不用上传”和“处理后得到副本”对使用者的具体含义。星潮是在线日报，不纳入这项承诺；个人空间也不承担保管结果文件的职责。[工具使用指南](../guides/features.md)

| | 桌面 | 手机 |
| --- | --- | --- |
| 构图 | 跟齐工具画廊的左右边界。浅暖纸色横条内，左侧放标题、右侧放正文，统一左对齐。保持右侧文字靠近标题，小段文字有余白即可。 | 随内容改为单列，标题在上、正文紧随其后。正文自然换行，温和底色帮助眼睛识别工具区已结束。 |
| 唯一的装饰 | 横条右上角用同色系稍深一阶的小折角，约 16～20 像素，像书的最后一页。墨色文字沿用首页，折角与妙压折页书呼应，尺度服从正文。 | 折角收小；文字放大或空间不足时可以隐去。装饰用 CSS 表现，不进入键盘顺序和读屏内容。 |
| 比例 | 标题先试 24～28 像素、正文 15～16 像素，左右内边距约 32～40 像素。目标高度约 140～180 像素。 | 两侧内边距约 20 像素，标题约 21～23 像素。375 像素宽时目标高度约 150～200 像素。以内容撑高，放大字号后允许超出目标。 |

沿用首页纸张与墨色的关系；视觉强度继续由上方星潮、纸蝶和折页书承担。这里不需要新的主插画、英文眉题、签名、悬停抬升或整块可点击的暗示。最后一张卡片、横条和页脚应放在同一张桌面截图里比较，尤其注意第三张卡片独占左栏时，收尾条能否自然结束这一排。空搜索时保留结果区已有的“重置”操作。

## 六、哪些新功能值得延伸

| 用户出现的困难 | 合适的功能与位置 | 启动条件 |
| --- | --- | --- |
| 想试效果，又不想先选择自己的文件 | 在对应工具的空状态提供“用示例试一次”，妙替用短文本演示前后差异，妙压用随包小图演示体积变化；运行现有处理流程。已经载入的材料应保留。 | 最值得单独验证的延伸。观察首次试用是否卡在选文件，再为确有问题的一款工具先做。 |
| 回访时总是重复找同一款工具 | 在首页搜索附近提供一个“上次打开的工具”快捷项，只保存本机工具标识，允许清除；首次访问、存储受限或工具下架时回到普通首页。 | 等工具数量增加、回访查找明显变慢时再做。当前三卡一眼可辨，在页末做快捷项反而需要多滚动。 |
| 用户读完仍反复问文件会不会上传、是否要登录 | 将反复出现的具体问题放进对应工具的选文件区域；若确实跨工具，再试一个可用键盘展开的短问答。 | 先收集实际提问。首页现阶段两句话能讲清，先避免额外操作。 |

以上功能均为候选，独立确认范围。首页这次优化本身可以不新增账号状态判断、存储、后端接口或埋点。

## 七、实施顺序与验收

1. **先选构图。** 用户确认方向后，在同一个工具列表、同一滚动位置对照 A 和 B 的桌面/手机预览，保留改前截图。重点看最后一张工具卡和页脚之间的节奏、正文是否读起来像聚妙屋，以及折角是否被误认为按钮。若首要目标是保留原句，改比 B 和 C。
2. **局部实现。** B 的代码预计只涉及首页 `section#about` 及其 scoped 样式。保留 `aria-labelledby` 与标题层级。删除旧按钮样式时检查它与搜索按钮共用的悬停、焦点选择器，以及其他入口仍在使用的箭头图标。工作范围从最后一张卡片之后开始，到全站页脚之前结束。
3. **布局与导航验收。** 在 320、375、760、761、1280、1440 像素宽和 200% 缩放下看换行、横向溢出、折角与正文的距离。检查三卡默认、筛选仅剩一项、零结果三种列表；用鼠标和 Tab 核对最后一张卡到页脚的顺序及可见焦点。分别验证访客能找到登录入口、登录用户能从头像和页脚进入个人空间；检查 `#about` 直达及浏览器后退滚动恢复。前端改动后执行 `npm run build` 及相关检查。
4. **检验模块是否值得留下。** 找 3～5 位不熟悉项目的人交替先看 A 或 B，让他们在无引导下完成三件事：判断压图是否上传、说明下载后原图怎样、找到自己的个人空间。记录实际回答与第一次找错的位置；不把小样本换算成全站转化率。若 B 能说清前两件事、账号仍好找，就保留；若两版表现相近，优先 A；若在选文件时才产生疑问，把说明移到工具内再评估首页。

**实施状态**　最终方案 A 已完成浏览器与前端工程验收，见[阶段记录](../dev-log/v1.0-dev.16.md#首页收尾区方案)。第六节的延伸功能仍为候选。
