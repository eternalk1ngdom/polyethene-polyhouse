# 文档、上下文与验证工作流整理

状态：**用户已批准，2026-11-01 完成交付**。仅治理文档与执行约束，不修改产品源码、依赖、数据库或私有运行配置。实施证据见 [v1.0-dev.9](../dev-log/v1.0-dev.9.md)。

## 批准范围与顺序

1. **验证按影响触发**：纯文档检查链接/一致性/差异；代码、脚本、SQL、配置按受影响层验证。保留实际执行与如实报告要求，不减安全、隔离、注释、布局和焦点底线。
2. **入口瘦身**：根日志仅存现状、下一步和索引；关闭已完成阶段的默认加载。旧入口留历史快照，历史结果不作为本轮新验收。
3. **按需检索**：策划书建章节与状态索引，原件只读；README 保留配置/运行/安全入口，详细教学移入按需材料；完整实现留磁盘，聊天不重发全文。
4. **会话交接**：在阶段“当前摘要”记录最小可核对交接；换任务/里程碑后建议新会话。先落盘再交接，不把压缩当作无损记忆或额度重置。
5. **验证与本地提交**：检查内容搬迁、链接、规则完整性、文件归属与必读字符量；不执行无关构建，不推送 GitHub。

## 验收边界

- 默认首次必读为 AGENTS + DEV_LOG + 当前阶段摘要，目标约 8000 字符；这是阅读预算，不是 tokenizer 实测或账单保证。必要源码、技能、批准范围与安全阅读另计。
- 不批量改写历史日志，不为每次提交/事件建新账本；计划保留批准条件，日志保留事实，索引只链接。
- 保留现有文档中的本地开发、部署搁置和依赖升级否决决定；妙替深化仍是本机待批准草案，不自动批准、实施或纳入此次提交。
- 不删除 target、依赖、技能安装备份或失败报告；它们不因存在磁盘就自动进入上下文，默认定向检索已绕开这些目录。
- 不降低测试质量，也不把“只改非业务文件”作为跳过有风险配置/迁移验证的理由。

后续以新会话的小任务观察是否能沿入口准确定位；出现遗漏则补摘要/索引，避免恢复全量强制阅读。无需为验证文档机制制造新的业务改动。
