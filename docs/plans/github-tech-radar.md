## 4. 采集、解读与历史口径

### 4.1 榜单事实

- 首批抓取全语言日榜，保留来源顺序、来源周期、来源链接及实际采集时间。筛选出的 Java 项目只是本期综合榜中的 Java 项目，不等同 Java 专属榜单。
- 按北京时间日期组织公开期号，分别保存采集、分析、发布时间；跨日执行的期号归属和原子发布规则在 G0 明确。补采只记录实际采集内容，不伪造过去榜单；历史从启用采集后积累。
- 总 Star、Fork、来源标注的本周期新增 Star 分别保存；新增 Star 不是自己按自然日差值重算。缺失与 0 分开，不补造指标或凑数。
- 区分有效少量结果与页面结构失效、登录页、限流页等异常。榜单主体无法可信识别时不发布；解析质量判据结合真实响应与脱敏夹具在 G0/G1 明确，不能用“非空”代替有效性检查。
- 优先使用 GitHub 仓库 ID 识别项目，处理改名、迁移、不可访问和归档状态；名称与 URL 不是永远不变的主键。

### 4.2 项目与 AI 解读

- 保存主语言、原始描述、必要目录线索、许可证及来源；许可证未识别时明确未确认，不承诺可商用。公开仓库不自动等同具备开源许可证的项目。
- 分类允许代码项目、文档资源、待确认，保留必要判断依据。无主语言或缺少根目录构建文件不能单独证明它是资料列表。
- 首批解读包括一句话定义、解决的问题、技术特点或适用场景、同类差异和限制。没有证据时允许暂无明确对标或结论，不强迫填商业平替。
- 区分作者陈述、可从资料核对的事实与模型推断；不把性能宣传写成实测结论。没有接入 HN 时不生成社区赞同、反对或口碑结论。
- 保存分析时间、资料版本、模型和解读规则版本，支持复用和追溯；只读历史引用当期已保存的内容，避免最新解读更新后改写旧报告。
- README、评论和模型输出均作为不可信内容，限制读取与输出大小、验证字段和枚举，前端转义展示；不执行材料中的指令，不自动克隆或运行项目代码。

### 4.3 保存边界

报告、项目身份、可复用解读、执行任务和费用记录分别表达职责。可以在现有单体与分层内实现，不为本模块改造全项目目录、权限或通用工作流。

已发布历史和必要版本长期保留；任务明细、错误摘要及原始抓取材料设置保留期、容量和清理边界，具体数值在 G0 记录。避免无限保存原始全文、响应和日志。表名遵守现有业务前缀，Redis 使用 `polyhouse:trend:…`；缓存不是归档的唯一存储。

## 5. 任务、权限与发布

### 5.1 统一执行流程

定时入口或屋主请求 → 接受任务、防重复 → 采集与有效性检查 → 补资料、分类与解读复用判断 → 预算允许的新分析 → 保存当期候选 → 发布并切换当前版本 → 更新缓存及任务结果。

- HTTP 提交返回任务编号，不等待整批外部分析；浏览器断开不取消已接受任务。相同请求编号返回同一执行事实；运行中不再启动第二批。同日新的明确更新意图可生成新版本，但仍受冷却、预算及任务限制。
- 持久保存接受和执行事实；任务存在运行时限。重启后识别中断与失去执行权的任务，不让状态永远运行中，也不盲目重放付费请求。
- 执行状态、发布状态和解读完整度分别表达。榜单有效但解读缺失可发布；失败更新保留原公开版本。事务提交完成后才对外切换，不公开中间写入结果。
- 外部 HTTP 在数据库事务外执行，落库和发布使用短事务。防重锁、超时、失去执行权及释放须核对所有者，旧任务不能覆盖新任务成果。
- 缓存故障允许受控回源数据库；防重机制不可用时停止接收新任务。Redis 写入失败不回滚成已发布报告丢失；数据库与缓存一致性方案在 G0 明确。

### 5.2 权限与接口能力

| 能力 | 访问范围 | 边界 |
| --- | --- | --- |
| 最新或指定日报、历史日期、项目解读 | 匿名可读 | 只返回已发布版本；无数据、已过期与缺失状态明确，不触发采集或 AI |
| 手动更新、任务内部状态、费用记录 | 仅 OWNER | 复用会话、最新账号状态及明确屋主业务校验；ADMIN、INSIDER 不获得此管理能力 |
| 付费调用入口 | 既有算力闸门加屋主限制 | 按契约保留 `@RequireRole(UserRoleEnum.INSIDER)`，同时满足 OWNER 操作范围，不能只靠接口命名授权 |
| 后台定时任务 | 服务端显式启用 | 不伪造登录身份，不依赖只对 MVC 生效的注解；独立遵守模块开关、预算和执行限制 |

G0 确定 DTO/VO、校验、稳定错误和有界查询；复用 `Result<T>`、已有请求封装及字符串大整数约定。前端所需时间、来源、分类与缺失状态先按业务提供，不命名为卡片或抽屉字段。内部堆栈、上游响应和凭据不作为公开错误返回。

新增公网读入口和高成本写入口须纳入现有请求预算与专项限制，验证正常突发、共享地址、并发、429/Retry-After 和恢复。公共鉴权和账号流程保持，不为内容缓存擅自移除现有响应保护；Redis 服务端缓存与浏览器缓存分别考虑。

## 6. 预算、外部调用与定时运行

### 6.1 费用

- AI 月预算人民币 10 元以内，自动、手动、重试及真实付费验收都计入约定范围；隔离测试不能各自重复放大真实预算。月份按北京时间归属，跨月预留和结算在 G0 明确。
- 请求前按输入、最大输出和允许重试预留费用，收到实际用量后结算；模型、价格口径及必要换算依据可追溯。并发预留不得超额；不使用无界重试。
- 超时可能已处理和计费，结果不明时保留预算占用并记录待核对，不自动重复扣费调用。预算不足停止新 AI 分析，继续提供已有内容及有效基础榜单。
- 应用保守估算不等同平台账单硬封顶；接入时核对实际账户计价和可用限制。具体模型在小样本质量、延迟和费用验证后记录，不把原文 `deepseek-chat` 或“低峰半价”永久写死。

### 6.2 外部连接

固定允许的数据源与安全重定向范围，限制连接/读取时限、响应体、并发、排队及重试；令牌只发往允许的目标，不接受用户任意 URL。GitHub 处理限流及条件请求；README 检查版本与新分析分开计量。具体模型并发不照抄固定 3，应结合现有实例预算验证。

密钥只在服务端私有环境中注入，未配置模块时不得阻止既有功能启动；不读取或展示私有预设来编写计划。客户端组件按职责放入模块相关生产包，不塞入纯函数 `utils/`。追加依赖前核对必要性、安全公告及实际触发条件，仅追加所需项，现有版本及 Vite proxy/alias/插件保持。

### 6.3 定时与部署边界

目标每天北京时间 06:30，显式使用 `Asia/Shanghai`，时间与启停可配置。有限补偿仅用于可安全确认的失败步骤，具体窗口、次数及退避在 G0/G2 验证后记录；不承诺五分钟完成，也不将漏采伪装成成功。

Render 免费实例可能休眠，应用内定时器不能唤醒停止的进程。本阶段验证运行中进程的定时调用，不承诺线上准时送达。持续运行或外部调度在部署阶段选择；如用外部触发，应另行设计机器认证，不长期保存屋主网页登录令牌。生产不得因合并代码而自动启用付费任务或改变部署。
