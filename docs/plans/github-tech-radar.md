## 4. 采集、解读与历史口径

### 4.1 榜单事实

- 首批抓取全语言日榜，保留来源顺序、来源周期、来源链接及实际采集时间。筛选出的 Java 项目只是本期综合榜中的 Java 项目，不等同 Java 专属榜单。
- 按北京时间日期组织公开期号，分别保存采集、分析、发布时间；跨日执行的期号归属和原子发布规则在 G0 明确。补采只记录实际采集内容，不伪造过去榜单；历史从启用采集后积累。
- 总 Star、Fork、来源标注的本周期新增 Star 分别保存；新增 Star 不是自己按自然日差值重算。缺失与 0 分开，不补造指标或凑数。
- 区分有效少量结果与页面结构失效、登录页、限流页等异常。榜单主体无法可信识别时不发布；解析质量判据结合真实响应与脱敏夹具在 G0/G1 明确，不能用“非空”代替有效性检查。
- 优先使用 GitHub 仓库 ID 识别项目，处理改名、迁移、不可访问和归档状态；名称与 URL 不是永远不变的主键。

### 4.2 项目与 AI 解读

- 保存主语言、原始描述、必要目录线索、许可证及来源；许可证未识别时明确未确认，不承诺可商用。公开仓库不自动等同具备开源许可证的项目。
- 分类允许代码项目、文档资源、待确认，保留必要判断依据。无主语言或缺少根目录构建文件不能单独证明它是资料列表。
- 首批解读包括一句话定义、解决的问题、技术特点或适用场景、同类差异和限制。没有证据时允许暂无明确对标或结论，不强迫填商业平替。
- 区分作者陈述、可从资料核对的事实与模型推断；不把性能宣传写成实测结论。没有接入 HN 时不生成社区赞同、反对或口碑结论。
- 保存分析时间、资料版本、模型和解读规则版本，支持复用和追溯；只读历史引用当期已保存的内容，避免最新解读更新后改写旧报告。
- README、评论和模型输出均作为不可信内容，限制读取与输出大小、验证字段和枚举，前端转义展示；不执行材料中的指令，不自动克隆或运行项目代码。

### 4.3 保存边界

报告、项目身份、可复用解读、执行任务和费用记录分别表达职责。可以在现有单体与分层内实现，不为本模块改造全项目目录、权限或通用工作流。

已发布历史和必要版本长期保留；任务明细、错误摘要及原始抓取材料设置保留期、容量和清理边界，具体数值在 G0 记录。避免无限保存原始全文、响应和日志。表名遵守现有业务前缀，Redis 使用 `polyhouse:trend:…`；缓存不是归档的唯一存储。

## 5. 任务、权限与发布

### 5.1 统一执行流程

定时入口或屋主请求 → 接受任务、防重复 → 采集与有效性检查 → 补资料、分类与解读复用判断 → 预算允许的新分析 → 保存当期候选 → 发布并切换当前版本 → 更新缓存及任务结果。

- HTTP 提交返回任务编号，不等待整批外部分析；浏览器断开不取消已接受任务。相同请求编号返回同一执行事实；运行中不再启动第二批。同日新的明确更新意图可生成新版本，但仍受冷却、预算及任务限制。
- 持久保存接受和执行事实；任务存在运行时限。重启后识别中断与失去执行权的任务，不让状态永远运行中，也不盲目重放付费请求。
- 执行状态、发布状态和解读完整度分别表达。榜单有效但解读缺失可发布；失败更新保留原公开版本。事务提交完成后才对外切换，不公开中间写入结果。
- 外部 HTTP 在数据库事务外执行，落库和发布使用短事务。防重锁、超时、失去执行权及释放须核对所有者，旧任务不能覆盖新任务成果。
- 缓存故障允许受控回源数据库；防重机制不可用时停止接收新任务。Redis 写入失败不回滚成已发布报告丢失；数据库与缓存一致性方案在 G0 明确。

### 5.2 权限与接口能力

| 能力 | 访问范围 | 边界 |
| --- | --- | --- |
| 最新或指定日报、历史日期、项目解读 | 匿名可读 | 只返回已发布版本；无数据、已过期与缺失状态明确，不触发采集或 AI |
| 手动更新、任务内部状态、费用记录 | 仅 OWNER | 复用会话、最新账号状态及明确屋主业务校验；ADMIN、INSIDER 不获得此管理能力 |
| 付费调用入口 | 既有算力闸门加屋主限制 | 按契约保留 `@RequireRole(UserRoleEnum.INSIDER)`，同时满足 OWNER 操作范围，不能只靠接口命名授权 |
| 后台定时任务 | 服务端显式启用 | 不伪造登录身份，不依赖只对 MVC 生效的注解；独立遵守模块开关、预算和执行限制 |

G0 确定 DTO/VO、校验、稳定错误和有界查询；复用 `Result<T>`、已有请求封装及字符串大整数约定。前端所需时间、来源、分类与缺失状态先按业务提供，不命名为卡片或抽屉字段。内部堆栈、上游响应和凭据不作为公开错误返回。

新增公网读入口和高成本写入口须纳入现有请求预算与专项限制，验证正常突发、共享地址、并发、429/Retry-After 和恢复。公共鉴权和账号流程保持，不为内容缓存擅自移除现有响应保护；Redis 服务端缓存与浏览器缓存分别考虑。

## 6. 预算、外部调用与定时运行

### 6.1 费用

- AI 月预算人民币 10 元以内，自动、手动、重试及真实付费验收都计入约定范围；隔离测试不能各自重复放大真实预算。月份按北京时间归属，跨月预留和结算在 G0 明确。
- 请求前按输入、最大输出和允许重试预留费用，收到实际用量后结算；模型、价格口径及必要换算依据可追溯。并发预留不得超额；不使用无界重试。
- 超时可能已处理和计费，结果不明时保留预算占用并记录待核对，不自动重复扣费调用。预算不足停止新 AI 分析，继续提供已有内容及有效基础榜单。
- 应用保守估算不等同平台账单硬封顶；接入时核对实际账户计价和可用限制。具体模型在小样本质量、延迟和费用验证后记录，不把原文 `deepseek-chat` 或“低峰半价”永久写死。

### 6.2 外部连接

固定允许的数据源与安全重定向范围，限制连接/读取时限、响应体、并发、排队及重试；令牌只发往允许的目标，不接受用户任意 URL。GitHub 处理限流及条件请求；README 检查版本与新分析分开计量。具体模型并发不照抄固定 3，应结合现有实例预算验证。

密钥只在服务端私有环境中注入，未配置模块时不得阻止既有功能启动；不读取或展示私有预设来编写计划。客户端组件按职责放入模块相关生产包，不塞入纯函数 `utils/`。追加依赖前核对必要性、安全公告及实际触发条件，仅追加所需项，现有版本及 Vite proxy/alias/插件保持。

### 6.3 定时与部署边界

目标每天北京时间 06:30，显式使用 `Asia/Shanghai`，时间与启停可配置。有限补偿仅用于可安全确认的失败步骤，具体窗口、次数及退避在 G0/G2 验证后记录；不承诺五分钟完成，也不将漏采伪装成成功。

Render 免费实例可能休眠，应用内定时器不能唤醒停止的进程。2026-11-16用户补充批准外部预热/限时保活的本地实现：独立Actions每五分钟在北京06:20～07:55请求匿名应用就绪接口，脚本08:00停止探测，配置默认关闭。它只唤醒，不触发生成、不保存屋主令牌；如以后新增外部生成触发，仍须单独设计机器认证。部署、远端启用及真实冷启动验收另行授权；GitHub调度可能延迟/丢失，不承诺线上准时送达。唤醒后既有已启用后台任务可能收费，仍受原配置及预算控制，不能因合并代码自动启用。细节见[运维步骤](../operations/trend-render-wake.md)及10.7。

## 10. G0 技术决定与首批契约

### 10.1 已实现的采集、归档和公开接口

- 单期最多取来源前 25 项。须有 `Trending` 标题、有效行、合法且不重复的仓库路径；关键标题损坏或全部 Star/Fork 指标消失拒绝整页。未知指标为 null，不凑数。
- 固定 HTTPS 来源及 GitHub API `2026-03-10` 版本，最多两次同源重定向；连接 5 秒、整个响应 15 秒、每响应 1 MiB、并发 1，无内部排队和自动重试。README 解码最多 256 KiB、清洗后五千字符，只在内存使用。单项目异常继续，限流/5xx/连接故障停止本轮 API 补全。
- 构建文件加源码目录才判代码工程；资源名称加纯资料根目录才判资源；其他待确认。不递归目录，也不根据无主语言排除。
- 追加 `010_trend_reports.sql` 两表：不可变公开 JSON 版本及按日期的当前版本指针，组合外键约束日期/版本一致，不动账号表。迁移和回退见[模块运维](../operations/github-tech-radar.md)。
- 期号归采集开始时的北京日期，跨日结束不改变归属；数据库时间统一 UTC 微秒。同日较早或相同采集时间的新候选不能覆盖较新内容。发布 UUID 幂等，旧 UUID 重放不重新切换指针；新版本与指针切换处于五秒短事务，用日期行锁串行。
- `GET /api/trend/periods`：`periodType` 省略为 DAILY，其他值拒绝；`before` 排他日期游标，`limit` 默认 14、最多 30，返回日期及 `nextBefore`。空库返回空列表。
- `GET /api/trend/report`：`periodType` 同上；省略 `periodKey` 读最新，指定则严格校验 `YYYY-MM-DD`。无报告 404、非法日期 400。基础报告明确 `insightComplete=false` 和项目未分析/无需分析状态，不冒充 AI 交付。
- 模块默认关闭且不自动迁移，关闭或存储未就绪返回安全503；不影响既有启动。公开读每实例60次/分钟、突发12、并发2、SQL三秒超时；429/Retry-After，不按来源建键、不信任转发头，生产还经全站预算。读取不恢复身份或触发外部生成；G3c可选内容Redis见10.6，默认不访问Redis，沿用no-store。

### 10.2 G3 设计依据与分步状态

- G3a已实现数据库单槽、唯一受理 UUID 和执行代数；区分待执行、运行、成功、部分成功、失败、中断。最多一个已受理任务，不排第二批；从受理起总时限30分钟、执行器心跳30秒、失活租约2分钟，使用数据库UTC时间。失去执行权的任务不得发布。
- G3a已实现重复 UUID 返回已有事实，忙时返回当前任务、不新受理，终结后新意图仍受60秒冷却；具体接口见10.4。G3b费用查询和保守关闭已实现，见10.5；内部信息仅 OWNER 可见。
- G3c定时默认关闭，默认06:30、Asia/Shanghai，明确采集失败后07:15最多补偿一次；各十分钟受理窗口，不重放进入AI/计费不明的执行，不伪造漏采旧期。线上休眠保障另行授权，具体见10.6。
- 发布版本长期保留，原始响应不落库；任务最多1000条，清理超过90天终结记录，定时映射随其清理。有RESERVED/UNKNOWN费用时保守保留任务上下文，满容量拒绝新意图，不删除费用。G3c单条内容缓存及权威版本验证见10.6。

后续参数可据实测调整，但必须维护身份、费用及 S1～S4 的批准边界，设计不表示代码已存在。

### 10.3 G2 已实现决定

- 用户选择官方接口，服务端固定HTTPS地址，不跟随重定向。只用现有JDK HTTP，不新增依赖；默认AI关闭，缺Key不影响启动。Key仅在认证头，配置和请求/响应诊断不输出密钥或正文，详见[安全配置](../operations/deepseek-key-safety.md)。
- 当前选定`deepseek-flash`，非思考/非流式/JSON模式，输出上限1500，连接5秒/整响应30秒、响应256KiB、请求32KiB、单并发、无自动重试。官方高峰CNY输入2/输出8元每百万token作保守计价；价格与模型的真实账户验证尚未完成，不能降低预留依赖缓存/低峰优惠。
- 追加011三表：月预算、每仓库执行槽及最近成功缓存、请求事实。锁顺序仓库→月份→请求；原子预留和十元CHECK防并发透支，结算/缓存同事务。北京月份在预留时确定，跨月仍结算原月份。字节数加512作输入保守上界，用量越界暂停当月新请求。
- 请求UUID由执行UUID和GitHub ID确定。重放不再收费；超时/无可信用量保留UNKNOWN和预留/槽，不自动退款重发。只有确定未发送才退额；内容非法但用量可信仍结算。鉴权/限流/连接等上游级失败停止本轮新调用，已有缓存仍能读取。
- SHA未变、模型/规则相同且未满15天复用；变化或到期才分析。预算/上游失败有旧解读时标STALE并保留原时间，明确文档资源不分析。模型输出严格校验字段、重复键、长度、分类和数组，项目明示限制与AI推断分开。发布冻结选中解读，G1旧JSON兼容。
- G2交付时入口只有内部`TrendAiService.enrich`；G3a随后追加受控HTTP任务入口，G3b费用接口见10.5。G4真实小样本走该任务入口和账本，证据见[阶段日志](../dev-log/v1.0-dev.15.md#g4b-官方模型小样本与对账2026-11-18)。

### 10.4 G3a 已实现决定

- `POST /api/manage/trend/jobs`仅接收`requestId` UUID，返回202和`accepted/replayed/job`；`GET /api/manage/trend/jobs?jobId=UUID`查询内部进度。复用DTO校验、Result/VO、no-store；Controller的OWNER范围与提交方法INSIDER闸门同时生效，服务短事务再核对当前会话、账号状态及精确OWNER角色。
- 追加012任务/单槽两表，任务不保存Token、Key、README或原始错误。受理时冻结操作者凭据版本及是否允许AI；任务开关`POLYHOUSE_TREND_JOBS_ENABLED`默认false，和模块/AI分别控制。未配置完整AI时拒绝新的AI任务，不暗中替用户打开任何开关。
- 一个后台工作线程、无内存排队；维护线程只负责领取/心跳，每30秒运行并支持有界唤醒，不是每日采集定时器。QUEUED可在重启后领取，过期RUNNING标INTERRUPTED、不自动重发；退出登录不撤销已受理意图，改密/重置、封禁或角色变化会阻止后续外部调用及发布。
- 每个GitHub请求/跳转和每个AI项目、预留前及发送前复核执行权。撤销不能被单项目降级吞掉；预留后尚未发送可取消，已发送但结果不明继续占用原账本，不因线程取消退款。已发出的远端请求不能保证撤回。
- 发布在操作者→单槽→日期的锁序内，版本插入、公开指针、任务终结和释放同事务；旧代不能发布或释放新槽。有缺失解读的有效日报标PARTIAL并保留reportId，包括明确未启用AI的基础日报；失败无reportId且保留故障阶段，旧日报不变。
- 管理路由独立每实例30次/分钟、突发6、并发2，先于认证拒绝；复用384KiB正文上界，生产继续受全站连接/读取限时等预算。冷却与入口限流均返回429/Retry-After，不写失败锁号、不信任伪造来源头。
- G3a历史验证见dev.15，后续费用闭环见10.5，定时/缓存见10.6；没有强杀真实JVM、完整真实账号/Redis/DeepSeek HTTP链路验收或开发库迁移，G4继续收口。

### 10.5 G3b 费用闭环已实现决定

- `GET /api/manage/trend/fees`只读单个北京月份及待核对页：省略月份取数据库时间对应的北京当前月；默认20、最大50项，UUID升序排他游标。返回当前配置上限、已计入/仍持有/剩余/人工保守部分及暂停状态；金额为人民币微元，不冒充平台余额或实际账单。原请求编号与任务编号分开。
- `POST /api/manage/trend/fees/resolutions`只允许精确OWNER显式确认`COUNT_RESERVED`，原预留至少五分钟、任务槽无活动采集后，将全部预留转入原月已用预算。保留旧解读，不补造token，不发起网络请求、不退款、不解除月份暂停；剩余预算不增加，不允许任意指定计费金额、退款或重置预算。
- 追加013不可变审计，处理UUID及原AI请求各自唯一。处理UUID、原请求、预留金额和固定理由必须与第一次意图相符；相同意图幂等，换号重复关闭或改意图409。`GET /api/manage/trend/fees/resolution`按处理UUID确认原事实，404不意味可以换号重做。
- 复用JWT/Redis/最新屋主角色及原管理路由预算、DTO/VO/Result/no-store；执行开关关闭时仍可查看并处理历史问题，不需要配置Key。该操作本身是既有费用的受控管理，不产生新的第三方收费，不扩大INSIDER权限。
- 操作者→任务单槽→仓库→月份→请求的锁序，费用/仓库槽/审计同短事务，失败回滚。过期任务先围栏后处理；已有关闭事实可在后续任务活动时重放。正常结算与人工关闭只能首次结算一次；晚到结果不能重算费用或更新成功缓存，晚到超界用量仍暂停原月份。
- 审计和费用长期保留，回退不退款、不恢复原预留；重新启用必须恢复原审计，不能只重建空表。迁移/回退和并发守恒仅在随机隔离MySQL验证；真实OWNER/Redis/DeepSeek端到端、TiDB及前端仍待验，定时/缓存后续结果见10.6。接口字段、步骤及错误见[模块运维](../operations/github-tech-radar.md)。

### 10.6 G3c 每日定时与内容缓存已实现决定

- 追加014：任务操作者/凭据版本允许同时为空，专门表示系统定时，并须匹配独立定时受理事实及显式开关，不创建虚构OWNER、不借用网页登录令牌。手动仍精确复核最新屋主；VO增加`trigger=MANUAL/SCHEDULED`。新模型兼容旧非空手动记录。
- 模块、任务、定时三个开关都启用，参数有效且AI配置可用（AI关闭时可发基础榜）才受理。`daily-time`默认06:30，时区固定Asia/Shanghai，45分钟后唯一补偿；首次及补偿各十分钟窗口。后台每30秒检查数据库时间，受理后共用原执行器、单槽、60秒冷却、容量、执行代数/租约、预算和原子发布；日期/尝试唯一，重启或多实例不会重复受理。
- 已有当期日报、已有该次尝试或活动任务均不新受理。补偿还须首次为明确FAILED/COLLECTING，且全局没有RESERVED/UNKNOWN费用；进入AI/发布阶段、已发布或中断都不补偿。窗口外不补造历史，停用定时会阻止系统任务后续调用及发布。应用内线程不能唤醒休眠实例，部署保障另行授权。
- 可选内容缓存默认关闭，最多一个`polyhouse:trend:view:latest` hash、三字段、900秒TTL，原始正文、费用和身份不缓存。每次读先查询数据库已发布版本头，缓存只接受相同ID/UTC微秒时间；不命中/损坏时读不可变版本并回填。主要加速最新日报，日期列表不缓存、历史通常回源；数据库不可用返回503，不用缓存掩盖发布状态不明。
- 两个Lua脚本原子读写，先检查字段/负载大小再读取，字符/UTF8字节有界；20位UTC微秒字符串比较，拒绝较早版本及相同时间不同ID，避免double丢精度。读取不续TTL。Redis故障暂停缓存尝试30秒，使用既有连接超时后回源；发布事务完全不依赖Redis。
- 014不是自动迁移；回退优先停定时并保留身份/映射。降级旧程序前停整个任务执行，不把系统NULL身份改成假用户；恢复012非空约束前须备份并明确处理系统任务。本轮只在随机库实测回退及保留手动/报告事实。
- G3c实现和隔离验收完成；定时线程实际触发链路在可控数据库时间/模拟外部服务下验证，真实Redis Lua用本机临时隔离容器、随机测试键验证并清理。并非真实平台认证/计费、实际06:30墙钟运行或云端准时验收，剩余由G4及部署阶段处理。

### 10.7 G3d 外部预热与限时保活
