## 1. 背景与屋主实测发现

首轮 B1～B4 落地并完成本机 8080 真实边界联调后，屋主亲自体验发现 3 项直接影响观感与效率的问题，同时要求对整条归档日期链路做一次深度架构自查，汇总后在下一轮集中闭环解决：

1. **工具栏折行破坏排版（实测图一）**：当以屋主身份登录（工具栏最右侧显示「星潮发布台」）且选中最新一期时，日期触发器内部额外出现 `最新` 胶囊，导致整行宽度超出 `.sheet`（`1110px`），挤掉右侧按钮转行，且在最新期与历史期间切换时工具栏高度反复抖动。
2. **无效 `<` `>` 箭头与刺眼的禁止光标（实测图二）**：当归档仅有单月（如当前仅有 `2026-11`）时，日历面板头部左右 `<` `>` 按钮永远不可点却仍占位置，且鼠标悬停弹出 `not-allowed` 禁止图标，产生“功能坏了/操作被拒”的负面观感。
3. **新增能力诉求：日历点选 + 手动输入日期融合**：希望同时支持鼠标点选日历与键盘直接输入日期，且需结合当前行业最前沿的交互与无障碍规范，妥善融合到“离散有值归档（非每日都有数据）”的业务场景中。
4. **架构自查优化**：全链路排查前端状态管理、请求去重、数据边界、组件可维护性与跨模块复用短板。

## 2. 问题一：工具栏单行保稳与日期触发器宽度恒定

### 2.1 根因像素账本（`TrendView.vue` `.sheet` 最大宽 `1110px`）

屋主态下 `.toolbar`（`gap: 10px 18px`）需容纳 6 个控件：

| 控件 | 现状估算宽度 | 问题说明 |
| --- | --- | --- |
| 视图切换 `.view-switch`（开源日报 \| 近 7 日风向） | `~196px` | 正常 |
| `<ArchiveDatePicker>`（左 `40` + 主体 `185` + 右 `40`） | **`~265px`** | 含 `最新` 胶囊多占 `~45px`，比旧 `<select>` 宽 `~120px` |
| `编程语言 [全部语言 ▾]` | `~170px` | 正常 |
| `技术分类 [全部分类 ▾]` | `~170px` | 正常 |
| `只看新面孔 (0)` | `~124px` | 正常 |
| `星潮发布台`（屋主专属） | `~102px` | 匿名巡检未登录导致漏测此按钮 |
| 5 处列间距（`5 × 18px`） | `90px` | 偏宽 |
| **合计** | **`~1117px` > `1110px`** | **选中最新期立刻溢出换行；切到历史日缩回 `~1072px` 造成行高跳动** |

### 2.2 根治方案

1. **触发器宽度彻底恒定（消除“有/无最新胶囊”导致的抖动）**：
   - 移除触发器内撑宽 `~45px` 的文字 `最新` 胶囊，保证选中任何日期时控件宽度 **100% 恒定**（零横向回流 / CLS = 0）。
   - “最新一期”语义改由以下两处零额外占宽方式承担：
     - 触发器 `aria-label` 与 `title` 保留「当前 2026-11-27（最新一期）」；
     - 面板内部当日格继续保留柔和主题细描边（`.is-latest`），且当处于非最新空月时仍保留底栏「回到最新月」兜底。
2. **紧凑化触发器与工具栏间距**：
   - 桌面端触发器左右切期箭头宽度由 `40px` 收敛为 `34px`（手机端 `≤640px` 仍维持 `44px` 触控热区）；结合第 4 节内联输入框（`10ch` 等宽数字区 + 紧凑日历按钮），整个 `<ArchiveDatePicker>` 桌面总宽稳定在 **`~198px`**（比现状净省 **`~67px`**）。
   - `TrendView.vue` `.toolbar` 桌面列间距从 `18px` 微调至 `12px`（5 处间距再省 **`30px`**）。
   - 优化后屋主全 6 控件总宽 **`~1020px`**，相对 `1110px` 容器留出 **`~90px` 安全冗余**，即使选中较长语言名（如 `TypeScript · 6`）或两位数新面孔数，在桌面端依然稳固单行不折行。
3. **验收补盲**：下一轮浏览器巡检必须覆盖**访客态（5 控件）+ 屋主/满控件态（6 控件含「星潮发布台」）**，逐一核查同一行 `boundingBox.y` 一致性与切换最新/历史日零跳动。

## 3. 问题二：无效导航控件隐藏与禁止光标治理

### 3.1 行业规范依据

根据 **GOV.UK Design System**、**Adam Silver (*Form Design Patterns*)** 与 **Material Design / React Aria** 的现代无障碍共识：
- **永远无意义的导航控件应直接不渲染**，而非长期展示灰显禁用按钮占据视觉注意力。
- **到达正常数据边界的禁用按钮（如最新一期不可再往后翻）不应使用 `cursor: not-allowed`**：红色/黑色禁止符号传递的是“违规/故障”情绪，而非“已到达边界”的平静状态；行业推崇采用低对比度弱化 + `disabled` / `aria-disabled="true"` + 平静的 `cursor: default`（配清晰的 `title` 说明如「已是最新一期」）。

### 3.2 分级处理细则

| 位置 | 触发条件 | 改造后表现 |
| --- | --- | --- |
| **日历面板头部 `<` / `>`** | 当归档仅覆盖 **1 个月**（`!canGoPrevMonth && !canGoNextMonth`，且在月份态 `!canGoPrevYear && !canGoNextYear`） | **直接隐藏（不渲染）**，零无效占位、零禁止图标 |
| **日历面板头部月份按钮** | 当归档仅覆盖 **1 个月**（`earliestYm === latestYm`） | 与单年保持完全一致的自适应逻辑：**退化为静态文本 `2026 年 11 月`**（无下拉箭头、不可点击）；一旦归档跨入第 2 个月，自动激活 `[ 11 月 ▾ ]` 与 `<` `>` 翻月按钮 |
| **日历面板头部 `<` / `>`** | 当归档跨 **多个月**，但当前停留在最早月或最晚月（仅一侧不可翻） | 保留双侧按钮以维持头部对称稳定，禁用侧改为 `cursor: default` + 轻度灰显 + `title="已是归档最早月份 / 最新月份"` |
| **外层触发器 `<` / `>`** | 整站仅有 **1 期**（`earliestDate === latestDate`）时自动隐藏；多期归档停在边界时保留 | 禁用侧改为 `cursor: default` + `title="已是最新一期 / 最早一期"`，不再出现禁止图标 |
| **月历无内容日期格** | 缺采日 / 建档前 / 未来自然日 | 保持灰显、`disabled`、`aria-disabled="true"` 且不可点击，光标改为 `cursor: default`（平息无意义红叉） |

## 4. 问题三：手动输入日期 + 日历点选的前沿融合方案

### 4.1 行业前沿调研结论（W3C WAI-ARIA APG / React Aria / DayPicker v9 / GOV.UK）

1. **复合形态标准（WAI-ARIA APG & React Aria `DatePicker`）**：
   - 将触发器设计为**单一统一外框的复合控件**：左侧是可直接键入的日期输入区域，右侧是独立的日历弹层切换按钮（`aria-haspopup="dialog"` + `aria-expanded`），外层统一承担 `:focus-within` 连续焦点外框（完美契合 `AGENTS.md` 铁律 8 复合控件焦点规范）。
2. **单文本输入框 vs 分段 `DateSegment` (`YYYY`/`MM`/`DD`) 取舍**：
   - **React Aria 严格三段式 `DateSegment`**：键盘上下键微调体验好，但在中文操作系统下存在显著工程风险——中文输入法（IME）合成期冲突、移动端软键盘跳段不稳、从聊天/文档一键复制粘贴 `2026/11/20` 或 `20261120` 易失灵。
   - **DayPicker v9 / shadcn / GOV.UK 推崇的「单原生 `<input>` + 宽容解析器 + 实时联动日历」**（**本项目强烈推荐**）：
     - 原生 `<input type="text" inputmode="numeric" autocomplete="off" spellcheck="false">` 天生免疫 IME 冲突，支持任意复制粘贴、退格修改、全选覆盖，屏幕阅读器兼容性最好。
     - 通过纯函数支持宽容输入格式：`2026-11-24`、`2026/11/24`、`2026.11.24`、`20261124`、`2026-1-5`（自动补零归一化为 `YYYY-MM-DD`）。
3. **离散归档场景的核心护城河（绝不盲跳 404，绝不静默吞掉用户输入）**：
   - 遵循 **GOV.UK** 校验原则：输入异常时**保留用户原文**便于修改，通过关联 `aria-invalid="true"` + `aria-describedby` 的轻量内联反馈条（浮于触发器下方或集成于打开的日历顶/底栏）明确告知原因并提供**一键修复**。

### 4.2 候选融合方案对比（推荐范式 A）

- **范式 A（推荐：触发器内联输入 + 日历按钮一体化）**
  ```text
  [ ‹ ] [ 2026-11-27  📅 ] [ › ]
  ```
  - **高频效率最高**：桌面端点击日期文字直接敲数字 + `Enter` 直达，免多点一步开弹层；点击右侧 `📅`（或按 `Alt+ArrowDown`）展开日历浮层。
  - **宽度极紧凑**：输入区固定 `10ch` 等宽字体（`tabular-nums`）+ `📅` 图标按钮，加上 `34px` 左右箭头，总宽约 `~198px`，比现版短 `~67px`，顺手根治问题一。
  - **移动端防误弹软键盘策略**：在 `≤640px` 触屏视口下，点击触发器打开底部抽屉浏览月历优先（不自动聚焦输入框弹软键盘遮屏）；底部抽屉顶部按需提供清晰的可输入栏（或明确点击输入框区域才拉起 `inputmode="numeric"` 数字键盘）。
- **范式 B（备选：触发器保持纯按钮，输入框置于日历面板顶部）**
  - 触发器维持 `[ ‹ ] [ 📅 2026-11-27 ▾ ] [ › ]`（仅去掉 `最新` 胶囊），点开日历面板后顶部展示「输入日期直达 `YYYY-MM-DD`」输入框。
  - 优点是实现更轻、外层完全无输入状态复杂度；缺点是键盘党每次手动输日期都要多点一次展开面板。

### 4.3 手动输入 4 类状态与闭环反馈设计（离散归档专用）

当用户敲完日期按 `Enter`（或点击提交按钮）时，按以下严格顺序校验，**非必要零网络请求**：

1. **格式非法 / 不存在的自然日**（如 `2026-02-30`、`2026-13-01`、`abc`）：
   - 保留输入原文，标记 `aria-invalid="true"`，展示内联提示：`请输入有效日期，如 2026-11-27`。
   - 按 `Esc` 或点击清除/还原即恢复为当前已选日期 `activeDate`。
2. **超出全局归档边界**（早于 `earliestDate` 或晚于 `latestDate`）：
   - 本地直接拦截（零请求），提示：`超出归档范围（2026-11-18 至 2026-11-27）`，并附带快捷跳转按钮（如早于最早则提供「跳到最早一期」，晚于最晚则提供「跳到最新一期」）。
3. **在边界内、对应月份已加载但当天无归档（缺采日）**：
   - 本地直接拦截（绝不跳转 404 页面），若日历已开则自动定位至该月，提示：`2026-11-20 当日暂无日报`，并调用纯函数 `findNearestAvailableDate(...)` 自动算出最近的相邻有值日，提供一键按钮 **`转到最近一期 (2026-11-19)`**！
4. **在边界内、对应月份尚未加载到本地缓存（历史月份）**：
   - 触发异步按月核验回调 `onEnsureMonth`（内部复用 `useTrendEdition.loadMonth(ym)`，带内存缓存、并发去重与 `AbortController` 取消隔离）；
   - 加载中展示微加载态，加载完成后：若存在该日 → 直接 `update:modelValue` 跳转并关闭弹层；若该日缺采 → 进入第 3 类「当日暂无日报 + 转到最近一期」引导；若遇 429/网络失败 → 保留原文并展示原位重试。
5. **无害失焦策略**：
   - 若用户改了一半未按 `Enter` 就点走失焦：若输入与原值相同或为空则静默恢复当前选中日期；若已解析出**合法且已知可用**日期则平滑提交，若非法/不可用则保留提示或按需回退，绝不静默跳转错日期。

## 5. 全面架构自查报告与优化清单

对 `TrendView.vue`、`useTrendEdition.ts`、`ArchiveDatePicker.vue`、`calendar.ts`、`trendReport.ts` 及后端 `TrendReportService.java` 全链路代码审查后，发现 **5 处前端结构性优化点**（后端检查零缺陷，无需改动）：

| 编号 | 级别 | 问题位置与现状 | 架构风险 | 计划优化方案 |
| --- | --- | --- | --- | --- |
| **A1** | 高 | [useTrendEdition.ts](../../polyhouse-web/src/features/trend/useTrendEdition.ts#L263-L279) 首屏 `loadDates()` 与 `loadMonth(currentYm)` 同时触发 | 首屏连续发送 `/api/trend/periods` 与 `/api/trend/periods?month=2026-11` 两次返回几乎相同的数据，白耗 `/api/trend/*` 限流突发额度（突发 12 / 并发 2） | 当首屏 `loadDates()` 返回已完整覆盖当月（`nextBefore === null` 或最旧项 `<= 当月 1 日`）时直接标记当月入 `loadedMonths` 免二次请求；并为 `loadMonth` 增加同月在途 Promise 去重（in-flight dedup） |
| **A2** | 高 | [ArchiveDatePicker.vue](../../polyhouse-web/src/components/ArchiveDatePicker.vue) 仅接收扁平 `availableDates` 与单一 `loadingMonth` | 组件无法区分“某历史月尚未拉取”与“该月已拉取但确实无日报”，翻月/手输跨月时易短暂闪现「本月暂无日报」或误判缺采 | 新增可选 `loadedMonths?: ReadonlySet<string>` 与异步核验回调 `resolveDate?: (isoDate: string) => Promise<ArchiveDateResolveResult>`，清晰区分「未加载 / 加载中 / 已加载无内容 / 已加载有内容」四态 |
| **A3** | 中 | [TrendView.vue](../../polyhouse-web/src/views/TrendView.vue#L64-L66) 将 URL `selectedDate` 无条件并入 `availableDates` | 若读者通过书签/地址栏访问一个 404 空日期（如 `?date=2026-11-10`），日历里该空日会被误标为有内容圆点且可重复点击 | 仅由 `report.value?.periodKey`（已证实发布）与后端 `dates.value` 组成 `availableDates`，彻底剔除未经证实的 URL `selectedDate` |
| **A4** | 中 | [ArchiveDatePicker.vue](../../polyhouse-web/src/components/ArchiveDatePicker.vue) 单文件已达 ~1360 行 | 叠加手动输入与异步核验状态机后会突破 1600+ 行，维护和单测粒度变重 | 保持唯一公共导出 `ArchiveDatePicker.vue` 不变，内部按职责拆分：`core/calendar.ts`（宽容解析 + 最近期查找纯函数）+ `components/archive-date-picker/useArchiveDateInput.ts`（输入/校验/取消隔离 composable）+ 精简视图层 |
| **A5** | 中低 | [ArchiveDatePicker.vue](../../polyhouse-web/src/components/ArchiveDatePicker.vue#L430-L440) Popover 写死 `left: 0` 且 `pointerdown` 全局监听常驻 | 作为全站可复用组件放到右侧筛选栏时浮层会向右溢出视口；关闭态仍常驻全局监听器 | 仅在 `open === true` 时动态挂载 `pointerdown` 监听、关闭立即解绑；打开时按 `getBoundingClientRect()` 自动检测右边界，不足时切 `right: 0` 防溢出 |

- **后端自查结论（[TrendReportService.java](../../polyhouse/src/main/java/com/polyethene/polyhouse/service/TrendReportService.java#L129-L148)）**：按月查询与全局边界查询均走主键覆盖索引、参数校验与互斥拦截完备、100% 向下兼容，**本轮后端零改动、零数据库迁移**。
