## 2026-10-27 每日成长奖励与一年满级

- **用户决定与规则：** 采用累计经验升级不清零、奖励按行为限次、经验/硬币/权限分离；参照 B 站曲线比例，将满级目标确定为累计登录 365 个不同上海自然日。每日首次有效登录发 10 经验和 1 硬币，PC/H5/PLUGIN 共用一次；中断不清零，不补签、不补发。Lv1～Lv6 累计门槛为 0/30/200/580/1370/3650，对应累计 0/3/20/58/137/365 天；满级之后继续累计经验与硬币，等级保持 6。这些规则覆盖上一节“仅有字段预留”的当时状态。
- **独立管理：** 新增 `UserGrowthService`/`UserGrowthServiceImpl`，唯一日结算方法 `rewardDailyLogin` 负责事务；`UserGrowthRules` 集中管理数值和等级计算，`UserGrowthConfig` 提供可测试的服务端时钟，`UserGrowthMapper` 负责持久化流水。Controller、前端和工具类均不发奖、不接收任意奖励数值；未增加收费/AI 接口。
- **认证接入：** 密码登录通过校验和审计更新后调用成长服务，已有有效 Token 的活跃访问/`me` 恢复也调用，因此用户无需每天退出重登。无效凭据、未登记会话、禁用和软注销账号不发奖；注册本身不发奖，退出与软注销本身不触发奖励。认证先于角色判断，已核验身份但业务返回 403 的当天访问也计作有效登录。
- **数据库与并发：** 追加 `003_daily_growth_rewards.sql` 创建 `sys_user_growth_reward`，主键为用户/行为/结算日，规则版本仅审计、不作为新的领取机会。固定顺序先锁用户行、再当前读流水，防止并发多发及旧可重复读快照漏掉新奖励；流水、经验、硬币、等级同事务提交。普通实体更新仍跳过成长属性，角色不被成长业务更改；溢出/存储故障返回安全 503 并回滚。
- **故障与注销边界：** 登录时成长服务加入原事务，Redis 发布失败会回滚审计、奖励和余额，允许重试；Redis 与 MySQL 仍非分布式事务。奖励故障会阻止当次认证完成，避免部分成功。软注销保留奖励记录；物理删除用户时仅级联其所属流水，测试以精确 ID/随机账号清理夹具。
- **前端需求，仅记录：** 账号区域显示 Lv 等级、当前累计经验、等级内进度、距离下级所需经验、满级状态和硬币余额；有效 Token 跨日恢复也应刷新数据，重复刷新不能重复弹出“领取成功”。奖励提示、今日领取状态和规则展示应由后端真实结果/后续只读契约驱动，不能以本地缓存当作入账凭据。本轮仅同步类型注释，不实现页面、进度条或奖励动画；保留 Figma 简洁方向与 Lusion 动态视觉待办。
- **其他行为与用途，未实施：** 当前只启用每日登录，不采纳浏览器自报本地工具完成次数作为发奖依据；未来行为奖励需新增真实核验、独立限次和结算流水，硬币消费规则仍待定。没有任意加经验/加币 HTTP 接口，也不自动开放角色权限。
- **实际验证：** 本机开发库追加 `003` 并重跑，流水表、主键、检查约束和归属外键存在，用户数量不变；`mvn -q compile -DskipTests`、`mvn -q test-compile` 及 `Invoke-LocalAuth.ps1 -Action Verify` 通过，全量 258 项无失败/错误/跳过，其中成长规则 15 项、真实成长事务 11 项，包含 365 天、多端/跨日、8 事务竞争（三次重复）、旧快照、规则版本防重、回滚重试与溢出；原认证/软注销并发回归继续通过。`npm run build` 与 5 项客户端会话测试通过，用户与奖励测试残留均为 0；用户已明确授权本轮提交并推送 GitHub，实际编号与远端结果以 Git 历史和最终汇报为准。
