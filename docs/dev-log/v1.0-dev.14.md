## 本机 WSL 故障恢复（2026-11-14）

- WSL 2.6.3 的 `--version` 能响应，`--status`、`--list --verbose` 超时，服务显示 Running，本机 6379 不可达。用户明确确认 Ubuntu/Docker 没有需要保留的运行任务，允许停止任务并重启 WSL。
- `docker desktop stop --force --timeout 12` 停止 Docker。管理员助手对 `wsl --shutdown` 设置 12 秒超时，该命令仍无响应。随后停止并重新启动 WslService，状态和发行版列表恢复；只对该服务操作，恢复结果存于忽略目录 `.local-backups/wsl-recovery-20261114/`。
- Ubuntu 可重新启动，`systemctl is-active redis-server` 返回 active，Linux Redis 和 Windows TCP PING 均得到 PONG。`Ensure-LocalRedis.ps1` 通过。`docker desktop start --timeout 30` 恢复 Docker 后，`docker info`、容器列表、Ubuntu 与 Redis 再次通过。
- 目前证明本次服务失响应已恢复，尚未定位长时间开机后复发的根因。Windows 有睡眠恢复与虚拟交换机告警，Linux 有 localhost 代理提示，均未建立因果证据。发行版、磁盘、WSL 版本与网络设置保留现状。项目 F1 浏览器验收仍待补。
