## 本轮交付

- 用户要求继续完成 P4。新增独立 `ProfileModerationService/Mapper/Controller`、DTO/VO、枚举与 008 三表，不把审核状态机放入认证或账号管理服务。原 `AvatarService` 只做认证/图像边界校验和委托，受限重新编码算法提取为纯字节 `AvatarImageUtils`，保留浏览器裁剪、256×256 与 256KiB 限制；删除已过时的 `AvatarVO`。
- 昵称与头像先申请后发布。每用户/字段独立版本，新申请替代同类旧待审；七天有效，只有有效 PENDING 可通过/驳回，终态不可再次发布。昵称只纯文本显示；定向更新单字段，不回写整份 User，不影响另一字段、经验、硬币或角色。
- 所有完整角色可提交自己资料，只有 OWNER 可审核/清点/下架；OWNER 自己也须显式批准。先按用户编号升序锁操作者/目标，再当前读字段和申请，核对最新会话、账号与申请版本。申请保存提交时凭据版本，封禁后解封/改密/重置也不能复活旧待审，后台尚未清理不代表仍可批准。
- 头像每天 5 次、昵称 2 次，上海自然日。成功申请入库计次，驳回/替代不退款；非法输入、文件错误或事务回滚不计次。升级当天叠加旧 ext_json 中头像次数，不改其他设置。相同用户/请求号/内容指纹返回原事实，不重复计次；复用请求号换内容/字段 409。
- 新头像地址为 POST `/api/auth/avatar/submissions`，旧 POST `/api/auth/avatar` 明确关闭为 409。选择新路径是为解决前后端版本混用：新页面访问旧后端 404，避免旧服务先公开图片后才被新前端解码拒绝。昵称、本人状态、私有图、审核队列/决定、公开清单及字段处置接口见[审核运维说明](../operations/profile-moderation.md)。
- 私有图位于公开目录同级 `avatars-pending`，无静态映射；本人/OWNER 带 Bearer 读取 JPEG，no-store/nosniff。组件使用 Blob 临时 URL，换图/换号/卸载即撤销；头像批准按钮等当前图片真实解码成功才可用，旧图事件不能放行新目标，后端仍独立检查。
- 当前公开目录不变，批准才生成新公开地址；提交/审计/字段状态同 MySQL 事务。文件回滚清理新图、保留旧资料/旧待审；成功后清理替代图/私有图，不把文件系统当作数据库事务。UNKNOWN 不误删可能提交的文件，私有孤儿超过 24 小时且数据库无引用才回收；公开未知孤儿仍需人工对照。
- 私有目录单实例最多 512 个图键（单张最多 256KiB，理论约 128MiB），每分钟最多处理 32 个失效申请和清理标记；缺少目录配置不回退 C 盘。路径/符号链接/目录文件/读取上限有防护。当前为单机单实例，OSS/多实例共享配额未实现。
- 个人中心局部增加昵称表单、近期状态/说明、额度及待审预览；裁剪器提示改为“提交头像审核”，不再把上传响应写入公开头像缓存。屋主从 `/manage` 新链接进入 `/manage/reviews`，查看待审与历史清单、明确原因后决定/下架；ADMIN/INSIDER 没有审核入口或权限。
- 历史字段不自动算已审，迁移不批量批准/重置真实屋主。OWNER 可从清单 KEEP 保留或 TAKEDOWN 恢复默认；下架使同类旧待审失效，历史 APPROVED 记录保留原事实。默认昵称采用 `ph` 序号，历史自定义登录名则采用用户编号作为后缀，不修改登录账号。
