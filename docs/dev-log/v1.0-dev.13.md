## 生产 API 分层限额（2026-11-09）

- CORS 处理合法预检后，实际请求先获取总额度，再有界读取请求体，最后才占用登录或敏感写入执行位并进入 MVC。这样慢速上传只占总并发，拒绝发生在查库、Redis 和 BCrypt 之前。超限返回 429/42900、`Retry-After`、`no-store`，跨域可读重试头。连接、账号状态和业务配额继续沿用既有规则。
- 三个固定大小的单实例令牌桶逐步恢复，初始值见[生产计划](../plans/render-docker-production.md#单实例-api-限额)。限额可由生产配置调整。不使用代理头作为限额键，不增加存储往返。单一来源仍可能消耗共享额度，来源隔离和多实例一致计数留给通过验收的公网入口。
- `mvn -q compile -DskipTests`、定向 `mvn -q -Dtest=ApiRequestBudgetTest,ProductionRateLimitHttpTest,ProductionHttpTest,AuthWebMvcTest,PolyhouseApplicationTests test` 共 41 项通过，覆盖速率恢复、并发拒绝、编码路径、请求体顺序、CORS 与默认 profile。令牌桶测试与实现同包，用于验证包内行为。前端 `npm run build` 和 `node --test "tests/user/*.test.mjs"` 共 115 项通过，继续使用已有 429 提示。 `docker build -t polyhouse:prod .` 通过。
- 新镜像以 `--memory=512m --memory-swap=512m --cpus=0.1` 运行，44.14 秒首次响应。验证普通四路并发、不同伪造转发头仍共用额度、合法预检、登录及敏感写入超限和恢复。一个慢速请求体不占登录执行位，六个在途请求体使第七个请求约 16 毫秒返回 429，断开后恢复。40 次短突发中 24 次进入鉴权、16 次在入口返回 429。内存峰值 153.4 MiB，退出 143，`OOMKilled=false`。本轮容器使用未登录和无效 DTO 验证限额，成功登录流程由受控 HTTP 夹具覆盖。
- 历史首笔登录 12.61 秒是容器开始响应后单独测量的首次登录，包含首次存储连接及业务执行，和 Render 从休眠到路由可用是两个阶段。公网先分段测量首访、首笔和后续登录，再决定登录单独的等待策略，登录写请求避免自动重放。

## 公网入口安全审查（2026-11-09）

- Render 免费 Web Service 空闲 15 分钟休眠，下一次入站请求唤醒。试用按真实访问验证首访等待，避免将每 14 分钟保活作为上线前提。服务内定时任务随进程休眠，定时保活也不能保障平台重启后的可用性。[Render 免费层](https://render.com/docs/free#spinning-down-on-idle)
- 登录先取用户，再做 BCrypt，生产已有 384 KiB 请求体上限和连接/线程预算，但没有请求速率限制。入口宜限制总量和突发，登录、验密、管理写入等单独限制，维持现有账号状态规则。当前审计地址取 Servlet 连接对端，不能直接作为 Render 用户地址；上线前验证代理覆盖可信头、伪造和旁路测试，再设限额。[Render 代理来源说明](https://render.com/articles/host-pocketbase-on-render) · [OWASP 认证指南](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)
- 静态核对 9 个 Mapper、调用处、MyBatis 资源与后台筛选。查询值走参数绑定，排序固定，账号前缀查询显式转义下划线，`FOR UPDATE` 是固定片段。审查范围内未发现请求值被拼成 SQL；未对公网执行攻击测试。前端未找到 `v-html` 或 `innerHTML` 渲染入口，现有浏览器本地存储中的 Bearer 令牌仍需靠脚本注入防护保护。
- 统一拦截器给 API 控制器响应加 `Cache-Control: no-store`，覆盖登录令牌、本人资料与鉴权失败。将敏感缓存、参数绑定、可信代理和入口预算并入 `AGENTS.md` 原安全条款。
- 当前 Tomcat 10.1.31 落在 CVE-2026-24880 的受影响版本范围。该公告的 HTTP/1.1 请求走私依赖前置代理放行异常分块扩展，本轮未在 Render 验证这一前提。继续遵守依赖版本冻结，公网放行前记录实际代理行为及处置。[Apache Tomcat 安全公告](https://tomcat.apache.org/security-10.html)
- `mvn -q compile -DskipTests` 和 8 组定向 HTTP 测试通过，共 69 项。`Invoke-LocalAuth.ps1 -Action Verify -AccountManagementOnly` 在隔离 MySQL/Redis 通过 14 项，包括前缀通配转义和角色分页，跳过 1 项可选浏览器测试。重建 `polyhouse:prod`，在 512 MiB、0.1 CPU 下实测未登录的 `/api/auth/me` 返回 401，同时带正确的 Pages CORS 与 `no-store`。周期保活和限流策略未接入，云端验收仍待授权。

## 3. 功能架构重构设计：头像上传与审核

### 3.1 既有方案痛点分析
- 原实现将图片存入本地磁盘，而 Render 容器属于**无状态文件系统（Ephemeral Filesystem）**，容器休眠或重建后本地文件会彻底丢失。
- 商业对象存储（OSS / COS）存在被恶意脚本刷爆下行流量导致欠费的经济风险。

### 3.2 新技术方案（前端 Canvas 降维 + 数据库 Base64 存储）
- **前端裁剪压缩**：
  - 上传前在前端通过 HTML5 Canvas 强制等比居中裁剪为 **160×160 像素**。
  - 导出为高质量 WebP 格式（画质系数 0.8），输出最多 **20 KiB**，简单图自然更小。
- **数据库持久化**：
  - 用户表新增 `avatar`（当前生效头像 Base64）与 `pending_avatar`（待审核头像 Base64）字段，类型为 `MEDIUMTEXT`。
  - 新增 `avatar_status` 状态字段（0-无待审，1-待审核，2-已驳回）。
  - 后端直接作为普通 JSON 接收，避免处理多部件文件传输（MultipartFile）。
- **风控防护**：
  - 后端校验 Base64 字符串长度不超过 60,000 字符。
  - 单用户每日最多 5 次。数据库按成功提交计数，Redis 保存提交后的计数并设置 24 小时 TTL。
