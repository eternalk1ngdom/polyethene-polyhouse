## 实施与数据流

- `utils/ruleLibrary.ts` 接收 `unknown` 并逐字段校验，投影为深冻结的 v1 数据；纯函数不访问浏览器存储或 UI。普通规则文本允许 `constructor` 等单词；未知对象字段、重复名称/ID/查找、非法 Unicode、时间与容量明确拒绝。
- `stores/ruleLibraryStorage.ts` 不提前接入 Pinia；显式创建和读取后才能保存。浏览器适配器延迟获取 localStorage，在 Web Locks 同名排他锁内比较原始快照并写入，拒绝陈旧实例覆盖；损坏数据保留原文并停止写入，锁/读写失败保留内存候选且不冒充持久化成功。
- 载入/保存/快照接口与依赖注入已完整实现，不是空骨架；当前页面没有调用它们，因此用户尚看不到词库功能。存储层不承诺拦截绕过锁协议的外部改写，真实浏览器双标签页及 UI 刷新验收留待 R2 接入。
- 词库总量按 UTF-8 字节限额，名称与规则长度按现内核的 UTF-16 代码单元；两者不是同一口径。专项测试首次失败为边界夹具按字符串长度补空格，已改为实际字节计算并重验通过，未为通过测试放宽上限。
- 最终审查发现 `/iu` 的 Unicode 大小写折叠会放行 `K`、`ſ` 等非 ASCII ID；先补用例复现失败，再改为显式 ASCII 大小写字符类。修正后全量测试、静态检查与构建重新通过。

## R3 规则草稿与历史恢复（2026-11-01）

- 用户选择“关标签后仍可恢复、本机保存并提供历史清理”，按批准第 0.2 节实现，不改词库容量、账号或文件处理。`utils/replaceDraft.ts` 只校验并冻结独立 v1 草稿/历史库，允许空字段、重复项及经 JSON 转义的编辑中代理项；这不代表可执行，原替换校验仍有效。每字段 200、最多 20 条；单稿 64 KiB、整库 768 KiB、10 份历史，满额拒绝，不静默淘汰。
- `stores/replaceDraftStorage.ts` 将开关、代次和页面槽位放在 `polyhouse:replace:draft:v1` 的一次 localStorage 写入中。页面持有自己的身份锁，所有修改在同名排他锁内重读并合并；各页只写自己的新 ID。历史清理需探测来源锁空闲，活动来源可复制但不能被删除；恢复非活动来源在新保存成功时原子移除旧副本，失败保留来源。关闭明确清空全部、更新代次，拒绝跨关闭/重开的迟到保存；坏数据不自动覆盖，只有明确关闭清理允许重置。
- `useReplaceDraft.ts` 管理 400ms 防抖、修改版本、恢复暂停及故障重试；`ReplaceDraftPanel.vue` 负责开关、历史选择/确认与浏览器事件。父页面只接入规则事件及路由补存守卫，沿用原 watch 清除旧任务/结果。sessionStorage 仅存本页上次 ID，清空后的空定位避免刷新又自动提示其他历史；不把规则放入 sessionStorage。定位失败单独提示，不冒充规则未保存或隐去恢复限制。
- 首次关闭且不写入；主动开启后后续页面记住选择。进入有旧稿时只提示，待决定期间不以空白或新输入覆盖；恢复不同非空编辑、删除历史、清空本页、关闭全部清理均明确确认。“保留当前编辑继续”保留历史；全空输入清除自己的草稿，字面空格仍有意义。隐藏/pagehide 尽力补存，站内离开等待补存，失败可返回或明确离开；强制关闭/崩溃不能保证末次输入落盘。依据：[页面可见性事件](https://developer.mozilla.org/en-US/docs/Web/API/Document/visibilitychange_event)。
- 实测修正：取消关闭时，受控 ElCheckbox 外观虽仍勾选，原生 input.checked 可能已变为 false；现在切换意图后重建开关，以确认状态为准，鼠标取消与键盘空格/Escape 均实际复验。其他页面删除待决历史会撤销失效选择/提示；删除非待决历史不重复保存当前稿。初次类型检查发现异步闭包故障阶段被 TS 过度收窄，改为可变状态对象；ESLint 的 const 要求同步修正，最终重验通过。
