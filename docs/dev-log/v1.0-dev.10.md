## 实施与数据流

- `utils/ruleLibrary.ts` 接收 `unknown` 并逐字段校验，投影为深冻结的 v1 数据；纯函数不访问浏览器存储或 UI。普通规则文本允许 `constructor` 等单词；未知对象字段、重复名称/ID/查找、非法 Unicode、时间与容量明确拒绝。
- `stores/ruleLibraryStorage.ts` 不提前接入 Pinia；显式创建和读取后才能保存。浏览器适配器延迟获取 localStorage，在 Web Locks 同名排他锁内比较原始快照并写入，拒绝陈旧实例覆盖；损坏数据保留原文并停止写入，锁/读写失败保留内存候选且不冒充持久化成功。
- 载入/保存/快照接口与依赖注入已完整实现，不是空骨架；当前页面没有调用它们，因此用户尚看不到词库功能。存储层不承诺拦截绕过锁协议的外部改写，真实浏览器双标签页及 UI 刷新验收留待 R2 接入。
- 词库总量按 UTF-8 字节限额，名称与规则长度按现内核的 UTF-16 代码单元；两者不是同一口径。专项测试首次失败为边界夹具按字符串长度补空格，已改为实际字节计算并重验通过，未为通过测试放宽上限。
- 最终审查发现 `/iu` 的 Unicode 大小写折叠会放行 `K`、`ſ` 等非 ASCII ID；先补用例复现失败，再改为显式 ASCII 大小写字符类。修正后全量测试、静态检查与构建重新通过。
