## 范围与顺序

**当前纠正：** 用户随后明确，先完善页面体验及账号功能，不继续推进测试体系；以下工程清单保留待办，不再代表自动执行顺序。当前先修首页平滑下滑，并比较低成本头像上传方案，头像实现待选型后推进。

用户暂不注册正式屋主，先完善基础，暂缓妙替/妙压等具体业务。现有前后端主干已支持本地开发，但不能宣称部署和基础配套全部完成。

1. **统一普通验收入口：** 一条命令检查前后端，明确区分普通测试和真实存储验收，不自动格式化或变更账号。
2. **独立测试数据库：** 把会创建 OWNER 夹具的实例测试与开发账号数据隔离，补迁移初始化、保护条件、清理和连接验证；当前本机实例入口仍使用开发库，尚未隔离。
3. **前端异常兜底：** 页面渲染/路由资源加载失败时给出可理解的恢复入口；现有 API 失败和会话恢复已处理，不重复重写。
4. **故障定位：** 为后端日志与错误响应建立安全的请求关联编号，覆盖生成/传递/清理，便于按一次请求定位问题；不记录密码或 Token。
5. **环境与迁移检查：** 统一检查运行环境、数据库迁移与服务连接状态，明确检查/实际修改的边界；现有私有预设和单项迁移保留复用。
6. **通用界面与可访问性复核：** 按实际重复和缺陷补空状态、加载/失败反馈、键盘与窄屏体验，不预造大量尚无使用场景的组件。

正式部署的 HTTPS、运行账号分权、备份恢复、自动化 CI、管理员二次验证及屋主恢复移交后续单独安排。当前 `docker-compose.yml` 的 `services` 为空，不能当作可运行部署。头像已按用户新要求进入方案讨论；资料编辑、社交、3D 和 AI 尚未展开。
