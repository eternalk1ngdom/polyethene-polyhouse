2. 人工执行 [005_account_security.sql](../../polyhouse/sql/005_account_security.sql)，再启动新版后端与前端。应用不会自动修改表。

迁移可以重跑，不清零已有安全状态；同名列已存在时跳过，不自动修正其他环境中不同的列定义。MySQL DDL 隐式提交，不能把整份迁移视为可事务回滚。

本机本轮迁移前已生成完整数据库备份，位于 Git 忽略的 `.local-backups/p1-account-security-20261029-175944.sql`，不提交、不公开。005 已在开发库执行并重跑；原有用户数量、唯一屋主及既有密码哈希/昵称/角色/状态/成长字段校验一致，新安全字段均为默认值。没有修改真实账号密码或授予 ADMIN；沿用原私有预设及运行密钥重启后端。

## HTTP 与页面契约

| 入口 | 实际行为 |
| --- | --- |
| `POST /api/auth/password/change` | Bearer 登录；JSON 仅需 `currentPassword`、`newPassword`，不接收目标编号/角色/版本；成功 HTTP 200，`Result` 的 `code=0,data=null` |
| `GET /api/auth/me` 及登录资料 | 在原脱敏字段基础上新增 `passwordChangeRequired: boolean`；不暴露密码哈希或凭据版本 |
| 初始改密受限会话 | 可以读 `/me`、改本人密码和退出；其他需完整身份的受保护业务返回 HTTP 403、业务码 `40301`；无效/撤销会话仍返回 401 |

当前密码和新密码均为 8～72 个字符且 UTF-8 最多 72 字节，不裁剪密码；新密码不能与当前密码相同。错误当前密码/非法输入返回 400；存储故障不能返回伪成功。DTO 的 JSON 输出和诊断字符串均隐藏凭据；前端不保存密码到全局状态或浏览器存储。

个人中心“账号管理 → 修改密码”打开独立弹窗；成功清理当前客户端身份，所有终端使用新密码重新登录。临时凭据自动进入同一弹窗，无法直接关闭，但可退出。新旧密码只驻留本次表单，提交结束、关闭、换号或卸载时清除；二次确认字段不提交服务器。

40301 只收紧同一已确认身份，不当成失效 Token 盲目清理；旧请求不能清理后来登录的新账号。网络/5xx 可能无法确认提交结果，页面不自动重发改密请求，提示重新登录核对。首次改密前不结算每日登录奖励，设置新密码后正常登录再按原有自然日规则结算一次；不新增额外奖励或公开领取接口。

## 安全事务如何工作

- `AccountSecurityService` 单独负责本人改密：校验 DTO/JWT → `FOR UPDATE` 锁定本人用户行 → 校验最新状态、凭据版本、Redis 会话及当前密码 → 定向更新哈希、版本加一、解除首次限制 → 写成功审计 → 撤销三端会话 → 提交。
- 登录、成长身份核验和软注销复用当前用户行锁/版本核对；不把旧整行 User 回写覆盖角色、余额和资料。头像直接服务调用和软注销的跳过 Bearer 拦截入口也补上首次改密限制，不能只依赖前端弹窗。
- 版本只增不减；历史未携带版本的 Token 仅解释为 0，并仍须匹配数据库及 Redis。负数、字符串、浮点、显式 null、越界等声明拒绝；显式 null 由已验签的有限长载荷额外辨别，新格式不重复解析 JSON。
- MySQL 变更和审计同事务回滚；Redis 不属于该事务。删除会话后再失败时，不恢复已经撤销的会话；数据库回滚后用户可用原密码重新登录。若提交结果未知，不自动重放，也不承诺两种存储一起回滚。数据库成功更新版本后，即使旧 Redis jti 被恢复，旧 Token 仍无效。
- 保留已有退出时“匹配当前 jti 后删除”逻辑；无错误次数锁定，不变更运行密钥。

## 四角色边界

`ADMIN=30` 已在前后端识别；USER/INSIDER/OWNER 仍保留。管理授权不是比较数字大小：ADMIN 不能通过 INSIDER 高开销门槛，INSIDER 不能通过 ADMIN 管理门槛。

`AccountAuthorizationPolicy` 已实现并测试精确动作矩阵：仅 OWNER 创建 USER/ADMIN；ADMIN 仅封禁 USER；OWNER 可封禁非 OWNER；仅 OWNER 解封、重置非 OWNER 密码与审核资源。**P2 已将创建策略用于真实开户接口；封禁、解封、重置和审核目前仍只是后续服务使用的授权函数。** 后续事务必须同时核对最新操作者/目标状态，不能拿页面角色或此静态函数代替数据库检查。

## 验证与隔离

普通验收仍使用 `polyhouse/scripts/Test-Project.ps1`，显式关闭真实实例开关。真实安全测试单独在仓库根目录运行：

```powershell
.\polyhouse\scripts\Invoke-LocalAuth.ps1 -Action Verify -AccountSecurityOnly
```

该入口复用忽略的本机预设，限制本机 MySQL/Redis，需要数据库创建临时库权限；创建随机 `polyhouse_security_*` 独立库，执行 001～005。HTTP 测试使用随机端口、隔离随机签名密钥和精确账号会话，结束删除本次库与夹具；不在真实开发库制造 OWNER，不执行旧的全量 OWNER 夹具。

真实验收覆盖：迁移重跑/旧 Token、三端撤销与其他账号隔离、首次限制及 multipart 头像绕过、错误/重复密码、两个改密并发仅一份成功、审计失败回滚、Redis 删除后失败回滚、恢复旧 jti 仍不能复活。普通测试另核对角色矩阵、拦截器上下文、声明类型与前端换号/跨标签旧回调。密码弹窗运行真实 Vue setup/watch/卸载测试，未将组件测试记作实际浏览器点击验收。
