# 唯一屋主初始化与部署注意事项

本文面向目前只在本机开发的维护者；是操作说明，不代表服务器部署、安全加固或屋主移交已经完成。

**当前本机状态（2026-10-27）：** 正式屋主已通过默认核对和显式 Apply 首次初始化；不在文档公开真实凭据。不得在这个数据库运行会创建 OWNER 夹具的全量实例测试，不得清空首次记录以便跑测试。以下初始化步骤保留供理解流程或新环境使用，不代表需要再次授予。

## 本机初始化步骤

1. 先人工执行追加迁移 [004_owner_bootstrap.sql](../../polyhouse/sql/004_owner_bootstrap.sql)。已有数据库不能重放 `001_init.sql`；迁移不会给任何账号授予权限。
2. 在网页正常注册自己的账号，保存好密码，在个人中心复制**用户编号和小写登录账号**。昵称不是登录账号，数据库账号也不是网站账号。
3. 在项目根目录的 PowerShell 或 IDEA Terminal 运行下面的只读检查，替换两个示例值：

```powershell
.\polyhouse\scripts\Initialize-Owner.ps1 -UserId "你的用户编号" -Username "你的登录账号"
```

4. 核对输出的编号、账号和当前角色，正式写入时加 `-Apply`：

```powershell
.\polyhouse\scripts\Initialize-Owner.ps1 -UserId "你的用户编号" -Username "你的登录账号" -Apply
```

5. 成功退出后重新登录。原 PC/H5/PLUGIN 会话已撤销，个人区域显示“聚妙屋屋主”。成长等级和屋主权限独立，初始化不会改变经验或硬币。

脚本复用 Git 忽略的 `polyhouse/.idea/workspace.xml` 中 `PolyhouseApplication` 数据库/Redis预设，不读取或要求网站密码，不改变运行密钥；连接环境在脚本退出后恢复。仅允许本机 `polyhouse_db` 和本机 Redis，不能拿本机脚本直接连接生产库。默认检查不修改角色、授权记录或会话，也不会预约名额，正式执行会重新核验。

## 已实现的保护

- **入口隔离：** `.ps1` 调用独立 Java `OwnerBootstrapCommand`，强制无 Web 模式，只装配存储与初始化服务，不扫描 Controller，也不开 HTTP 端口。普通应用启动固定走 `PolyhouseApplication`，不会自动执行授权；无公开授予接口，无“第一个注册用户自动成为屋主”规则。
- **目标确认：** 必须同时精确匹配编号和数据库规范用户名，拒绝大小写修正、裁剪、未知参数、禁用和注销账号。公开编号/用户名只是防误操作核对项，不能证明身份，也不能代替服务器执行权限。
- **并发和唯一性：** 实际初始化先锁单行初始化槽，再锁目标用户，多个命令串行。`sys_user.owner_slot` 是自动生成列，角色为 OWNER 时等于 1，其他角色为 NULL；唯一索引从数据库层保证包括禁用/软删除账号在内最多一个屋主。命令核验生成表达式和单列唯一索引，未迁移或结构异常时拒绝执行。原理见 [MySQL 唯一索引说明](https://dev.mysql.com/doc/refman/8.0/en/create-index.html)。
- **首次记录：** `sys_owner_bootstrap` 单行记录首次目标、原角色、执行 Java 进程的操作系统账号和数据库时间，与角色一起提交；它不会因用户被物理删除而丢失。同一屋主重复执行不改首次记录，仍撤销会话以支持结果不确定后的重试。已有同一正常 OWNER 但尚无记录时，首次确认会记录原角色 OWNER；已有另一屋主或历史记录不一致则拒绝。
- **失败语义：** Redis 清理失败会使角色和初始化记录回滚。Redis 不参与 MySQL 事务，已经删除的旧会话不会恢复，可能需要重新登录；不能因此认定授权成功。数据库提交结果或网络结果不确定时，先重新只读检查，再对同一账号重试，不改表强行“修好”。
- **防误注销：** 服务端在用户行锁内读取最新角色，OWNER 调用普通注销返回 403，用户记录与会话保留；旧 USER Token 也不能绕过。前端禁用注销按钮并说明原因，角色变为 OWNER 时旧确认失效；正常退出登录仍可用。
- **在途请求：** 认证读取用户角色后再次核对 Redis 会话；旧 Token 即使在等待用户行锁前已经通过初检，也不能在初始化撤销后取得新屋主身份。

## 部署前必须弄清的权限边界

1. **网站账号和运维账号是两套身份。** 网页 Token 只能调用已开放的业务接口；运行脚本需要操作系统执行权限、私有配置读取权限和数据库写权限。有人看见源码，不等于能够执行授权；但取得这些运维权限的人可以修改数据库，不能承诺“绝无可能”。
2. **脚本属于运维目录。** 不放在 `polyhouse-web/public/`、Nginx 静态根目录或上传目录；不提供“运行脚本/任意命令”的 HTTP 接口，不将运维目录映射成静态资源。不依赖隐藏文件名或保密源码保护入口。
3. **真实凭据属于私有运行环境。** 不提交数据库密码、JWT 密钥、Token、IDEA 个人配置，不把这些粘贴到聊天、文档或终端命令行。生产使用受限的配置/密钥管理和文件权限，本机 IDEA 预设不是生产密钥管理方案。
4. **部署迁移与网站运行分权。** 本机开发预设当前使用开发数据库账号，不把这一授权范围直接照搬到生产。生产迁移账号、屋主初始化运维账号和应用运行账号应分别配置；按实际需要授予表/列权限，避免网站运行账号拥有建表、删库或任意修改角色/初始化审计的权限。
5. **仅向需要的网络开放端口。** 正式站点使用 HTTPS；MySQL/Redis 不直接暴露公网，限制 SSH/远程桌面及服务器文件访问；网站自身也不提供控制服务器的入口。操作系统、网络、备份与恢复配置须在正式部署阶段逐项验收。
6. **执行记录有边界。** 数据库记录的是操作系统账号名，并非经过独立认证的企业审计身份；掌握数据库管理权限的人也可能改写它。正式上线按规模增加集中审计、运维访问控制和管理员二次验证，不把当前单行记录宣称为防篡改审计系统。权限设计参考 [OWASP 授权指南](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)。

## 不要自行“修复”的情况

- 已存在另一屋主、重复屋主、缺少唯一约束，或初始化记录和账号不一致：停止执行，保留数据核对；迁移不会自动挑选屋主或降权任何账号。
- 屋主密码丢失、账号被禁用、误降权或物理删除：当前不提供恢复/移交命令，也不允许通过重复初始化抢占。后续应设计独立的受控恢复/移交流程；不要清空初始化记录来绕过。
- 目前禁止普通注销屋主，并不等于禁止数据库管理员直接改库、封禁或删除。数据库管理权限本身必须受控。

## 验收与测试数据

私有预设全量验收入口仍为 `polyhouse/scripts/Invoke-LocalAuth.ps1 -Action Verify`。屋主实例测试临时创建 `owner_it_` 随机账号，在真实 MySQL/Redis 中验证只读、提交、防重、并发、回滚及独立命令进程；只按登记的精确 ID/用户名清理自身账号、流水、会话和初始化记录，不提供任何生产重置功能。

由于全库只能有一个屋主，**正式初始化自己的账号后，不要在同一个数据库运行会创建 OWNER 夹具的全量测试**。使用独立测试数据库/实例并完成迁移；本机预设入口仍只允许开发库，生产验收环境的配置应在部署阶段独立安排。测试不会为运行方便而降级、删除或清空你的真实屋主。
