# 现有规模容量与故障恢复验收

日期：2026-10-28；范围为已有账号、头像及妙替功能，不升级依赖、不扩大规模。结论：本机有限负载与所列故障恢复通过，可以回到功能试用；不等于生产容量认证或覆盖所有崩溃时序。

## 可复用入口

- 项目根目录：`.\polyhouse\scripts\Test-CapacityRecovery.ps1`。复用忽略的私有预设，固定 Maven 仅选择 `CapacityRecoveryIntegrationTest`；入口先核对本机 Maven 支持 `MAVEN_ARGS`，否则拒绝执行。需要本机 MySQL 建库权限和 Ubuntu WSL Redis，不是生产运维命令。
- `polyhouse-web/`：`node benchmarks/poly-replace-pipeline.mjs`。三组负载，每组独立进程运行三次，精确核对解压文件数量、全文 SHA-256 和命中次数；生成随机 `target` 素材并在结束清理，摘要位于 `polyhouse/target/polyreplace-pipeline-results.json`。
- 普通验收仍为 `Test-Project.ps1`；显式关闭新增容量验收开关，连同原有真实连接测试一起跳过，不自动重跑隔离验收或性能基准。额外以进程 `MAVEN_ARGS` 故意开启容量开关运行普通入口，命令行关闭仍生效，隔离套件保持跳过。

## 后端隔离与有限负载

测试按随机名称创建 `polyhouse_acceptance_<32位十六进制>` 库，在该库执行现有 001～004 SQL，初始化脚本中的默认建库/USE 不执行；独立随机 HTTP 端口、`target` 头像目录，不复制现有用户。Redis 服务共用，但只使用新建普通账号精确雪花 ID 对应的 PC 键，并先检查未占用；不使用 FLUSH/SCAN。故障由两个只监听 127.0.0.1 随机端口的转发器制造，不停止真实服务、不切断其他客户端。

正常路径：真实 HTTP 注册/登录后，4 条并行请求链各访问 `/me` 与 `/growth` 共 40 次；最终一轮总耗时 262 ms，p50 26 ms、p95 39 ms、最大 44 ms，全部成功，经验仍为 10、每日流水只有 1 条。数据来自一轮本机有限样本，未测后端峰值内存、长时间负载或最大并发，不能外推吞吐上限。

| 故障/恢复 | 实际断言 |
| --- | --- |
| Redis 连接切断 | 当前用户和软注销返回 503；账号 deleted 仍为 0；恢复转发后原 Token 可用，无需重启应用 |
| MySQL 连接切断 | 当前用户返回统一 500；恢复连接后原 Token 可用，经验和当日流水不重复 |
| 头像目录是同名普通文件 | 上传返回 503、不写今日次数；清除故障后成功，剩余 4 次 |
| 头像资源读取 | 新头像 GET 200，带 `max-age=86400` 缓存头 |
| 旧图删除失败 | 产生磁盘清理标记；移除阻碍后新存储实例执行重试，旧图与标记均消失 |
| 退出与清理 | 退出后 `/me` 为 401；精确会话不存在；应用关闭后临时库及图片目录删除并断言成功 |

故障恢复观测值：恢复转发后 Redis 141 ms、MySQL 23 ms。测试实例特意使用 500 ms Redis 超时、1 s 连接池等待和 1.5 s JDBC socket 超时，均仅在测试内覆盖，生产配置未改动；这些数值不是默认配置的恢复 SLA。这里模拟的是连接被关闭/拒绝，不是丢包黑洞或整机停机。清理重试使用新存储实例，不能当作真实进程被强杀后重启验收。

## 妙替流水线与内存

Node v24.22.1，真实生产解码、AC 替换、ZIP 和缓冲区传输，通过 Node `worker_threads` 适配通信；计入文件读取和 Worker 启动，不含页面渲染、下载和解压校验。每组 20 条规则；三次中位耗时，内存列为三次观察范围。

| 样本 | 中位耗时 | 进程驻留内存观察峰值 | 相对空闲进程增量 |
| --- | --- | --- | --- |
| 20 文件、5 MiB，无匹配 | 235.8 ms | 112.6～116.9 MiB | 55.4～60.0 MiB |
| 20 文件、5 MiB，1,310,720 处命中 | 301.8 ms | 137.9～142.3 MiB | 80.9～85.3 MiB |
| 2 文件、2 MiB 输入，扩展为 16 MiB 输出 | 438.0 ms | 233.5～234.3 MiB | 176.3～177.3 MiB |

RSS 为整个样本进程及 Worker 的驻留内存，采用主线程 5 ms 抽样和操作系统 maxRSS 取较大值；包括运行时开销，不是纯算法堆大小。它不是浏览器页面/Worker 的精确峰值，也不证明没有遗漏瞬时分配。输出扩展场景的内存增量明显大于输入大小，因此保持 20 文件/5 MiB 输入/16 MiB 输出的现有限制，不据此扩容。

实际浏览器选择 20 文件、总计 5 MiB，以 `abc→Z` 处理，三次均显示 1,310,720 处，点击到结果可见为 646/888/1109 ms，包含自动化往返开销。一次批量计时/下载工具调用超时后改为短超时操作，以上仅记录后来完成的三次；本轮未重复完成真实下载字节核对，Node 的九次完整 ZIP 解压哈希校验均通过。真实页面尝试点击取消时任务已结束，不能算作本轮浏览器取消成功。

新增四项真实 Vue 组件生命周期回归：控制未结束的读取及 Worker 替身，覆盖读取后取消、旧成功/旧错误迟到、新任务忙碌状态、规则/编码快照变化、移除、离页终止和失败重试。可重复证明 UI 作废旧任务的行为；不能宣称已覆盖真实 Worker 内替换/压缩各阶段的取消压力。
