# 现有项目审查：2026-10-28

## 结论与范围

暂停第二项工具妙压，先巩固现有能力。本轮是代码审查、已有验收复跑及有限性能测量，没有修改业务代码、依赖、数据库结构、真实账号权限或运行密钥。

现有账号与妙替主线通过本轮测试，未发现可在这些测试中复现的越权、重复奖励或部分成功导出。仍有需要处理的依赖安全维护和容量边界，不能据此宣称“没有漏洞”或“整体性能优秀”，也不能等同上线安全验收。

阅读范围：根工程约束、当前阶段日志、只读策划书、前后端目录及生产实现；重点逐条跟踪认证、角色、退出/注销、屋主初始化、成长事务、头像处理/资源访问、前端会话竞态、妙替内核/Worker/导出、迁移及本机脚本。历史日志仅作当前入口引用，不批量重审全部归档；第三方依赖源码和技能数据库未逐文件审计。

## 按优先级处理的发现

### 1. 高优先级：后端依赖安全基线过旧（尚未升级）

- Maven 实际解析：Spring Boot 3.3.5、Spring Web/MVC 6.1.14、Tomcat 10.1.31、Netty 4.1.114.Final。依据为依赖树及实际 Surefire 运行类路径，并非只读声明版本。
- [Spring CVE-2026-22745](https://spring.io/security/cve-2026-22745/) 涉及 Windows 上文件系统静态资源解析的拒绝服务，6.1.14 落在公告范围。项目使用 Windows、Spring MVC 与磁盘头像映射，符合公告列出的环境条件；自定义解析器先限制 UUID 文件名，缩小了入口，但本轮没有构造攻击验证，不能认为白名单已经替代框架修复。
- [Tomcat 官方公告](https://tomcat.apache.org/security-10.html) 的 CVE-2025-48988 涉及 multipart 上传拒绝服务，10.1.31 在受影响范围，项目启用了头像上传。已有 256 KiB 文件和 272 KiB 请求上限，但仍应核对容器对分段数量、头部和连接资源的限制，不能仅凭小文件上限宣布不受影响。本轮未执行耗尽内存的攻击。
- 不把所有旧版本公告都称为当前可利用漏洞：例如 [CVE-2025-41242](https://spring.io/security/cve-2025-41242/) 官方说明默认安全设置的 Tomcat 可阻断相应路径穿越；[CVE-2026-41843](https://spring.io/security/cve-2026-41843/) 要求版本化资源配置，当前头像配置没有启用该能力。
- 按 AGENTS.md“需要升级先问我”，本轮未改 pom.xml。下一步应单独提出受支持的 Boot/JDK/MyBatis 兼容升级方案，以执行时的最新公告选目标，再完整回归；不要只停在上述某一个 CVE 的最早修复版。尚未对全部 Maven 传递依赖运行完整漏洞数据库扫描。

### 2. 上线前高优先级：公开入口缺少防滥用预算（尚未实现）

- 注册/登录都有字段校验、BCrypt 和模糊错误，但没有按来源及整体容量限制请求的机制。连续请求仍可消耗密码哈希 CPU、数据库连接和账号存储。
- 头像每日 5 次约束的是成功更新；不能代替请求级流量限制。multipart 解析发生在 MVC 身份拦截之前，不能把认证拦截器当作上传解析的资源屏障。
- 建议入口层限制请求体、并发和速率，业务层保留额度；代理后的来源只信任明确配置的代理。继续保留用户已要求的“密码错误立即重试”，不恢复五次错误锁号。
- 当前仍是本地开发配置：数据库账号默认 root、MySQL 默认连接关闭 TLS、Redis 本机无认证、CORS 含扩展通配来源、未指定 server.address。它们不是公网部署配置。实际防火墙、监听暴露及反向代理没有在本轮验收；上线需独立落实最小数据库权限、网络隔离、HTTPS 和明确来源。

### 3. 性能优先级：认证链路存在重复工作（尚未改动）

- `GET /api/auth/me`：拦截器调用 `AuthService.getCurrentUser`，Controller 再调用一次。每次都会校验 JWT、两次读 Redis、进入成长事务锁住用户并查当天流水；当天已结算的正常请求仍合计约 4 次 Redis 读取、4 次 SQL 查询及两次事务边界。
- `GET /api/auth/growth`：拦截器先结算/认证，服务再核会话并读取成长快照，同样有重复读和行锁。头像链路也多次复核身份。
- 这些锁和二次检查保护了并发发奖、注销、屋主升权撤销等边界；本轮没有直接删除它们。未来可先复用请求内已经核验的资料，再把纯身份读取和每日结算职责拆清；写业务仍在行锁内复核。优化必须回归并发与撤销，不能缓存旧角色长期放行。
- 虚拟线程让线程等待更轻，不增加数据库连接数，也不消除同一用户行锁竞争。本轮未测后端吞吐量、P95/P99、连接池饱和及依赖故障时的排队。

### 4. 存储可靠性：异常退出与部署边界仍在（尚未实现）

- 头像本体在独立磁盘目录，数据库仅保存路径；重新编码、大小/像素限制、随机文件名和公开路径白名单均已存在。图片 HTTP 缓存与账号接口分开，不会每次读取图片都查用户或解码。
- 事务回调可以补偿已知提交/回滚，磁盘标记可以重试删除失败。但进程在“新图写盘后、数据库提交/回调前”崩溃，仍可能留下未引用文件；UNKNOWN 事务状态也刻意保留文件。没有启动后的孤儿核对、备份恢复和容量告警，不应把当前补偿称为崩溃后的完整一致性方案。
- 建议后续按宽限期核对数据库引用与磁盘文件，先只读报告，再设计可恢复清理；不直接扫描删除用户图片。多实例上线再处理共享存储/OSS 与备份。
- Redis 不可用时拒绝认证是既有安全决定；WSL 保持运行和启动 PONG 只改善本机启动可用性。IDEA 直接启动、运行期断网/停服、Windows 重启后的恢复不因此自动解决。数据库与 Redis 不属于同一个原子事务，Redis 已撤销后 MySQL 回滚可能导致用户需要重新登录，这是明确的安全取舍。

### 5. 妙替资源与功能边界（保持现状）

- 反向 AC 内核按原文最左起点、同起点最长规则消费，不执行正则、不再次替换新结果；编译规则可复用于同批文件。Worker 承担替换及 ZIP，离开页面/取消会销毁旧 Worker，旧读取结果通过任务版本丢弃。
- 输入最多 20 个文件、单个 2 MiB、总计 5 MiB；输出单个 8 MiB、整批 16 MiB，另有字符上限。路径穿越、规范化重名、坏编码及输出膨胀有对应测试。
- 密集命中会生成大量临时片段；所有输出与同步 ZIP 仍同时占内存。输出大小限制不等于峰值内存限制，纯浏览器处理也不等于低内存。未做浏览器/Worker 峰值内存和低配设备压力验收，不提高上限。
- Python 等源码按文本整体处理，不能识别“只替换注释”；当前文件选择器 accept 未列 .py，文件夹模式不按后缀筛选。大型项目常超过 20 文件，且未跳过 .git/.venv 等目录，不能称为整仓库代码重构工具。
- NUL 检查不能识别全部二进制文件；不支持自动可靠识别编码、混合编码逐文件设置、原编码导出、原位写回。以上是已有边界，不在审查中擅自扩展功能。

### 6. 前端会话与加载（本轮未发现新缺陷）

- 响应运行时校验、大整数按字符串传输、不信任本地角色、旧响应版本检查、多标签共享缓存复核、网络故障与 401 分开处理均已实现。未发现 v-html、eval 或把用户文本作为 HTML 执行的路径。
- Token 使用 localStorage；一旦将来引入可执行脚本注入，Token 可被读取。当前不据此宣称发生 XSS；上线时另行制定内容安全策略和脚本来源策略。普通注销的双重确认属于前端防误操作，最终 OWNER 禁止注销及身份校验仍在后端。
- 页面路由已分块。当前全量引入 Element Plus CSS，构建主样式 383.36 kB、gzip 52.81 kB；入口 JS 块 224.28 kB、gzip 79.00 kB，另有共享块，不能把入口块大小当作完整首屏流量。可后续测首屏网络与渲染，再评估样式按需加载，不为体积数字修改既有构建配置。
- 妙压和云端规则相关类仍是骨架，无公开业务接口；继续暂缓。

## 下一步顺序

1. 用户确认后制定并实施后端依赖兼容升级，复核官方公告与受支持版本；完整回归鉴权/上传/事务，真实 OWNER 夹具放独立测试库。
2. 先消除同请求重复认证，再评估每日结算的读写拆分；同步测 HTTP 延迟、SQL/Redis 次数与并发，保留撤销和降权即时生效。
3. 统一现有账号、头像、妙替的边界反馈；按用户实际试用决定 Python 文件选择及注释范围等功能，不扩展第二工具。
4. 在独立测试环境补容量、防滥用、磁盘/依赖恢复及备份验收；再据数据决定内存和样式优化。正式公网部署另立范围。
