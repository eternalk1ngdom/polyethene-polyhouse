# P2 屋主受控开户

本模块属于[已批准内测计划](../plans/controlled-beta-account-management.md)的 P2，基于 [P1 账号安全](account-security.md)。不包含账号列表、封禁/解封、代重置密码或资料审核；这些依次在 P3/P4 实施，不代表已经可以公开上线。

## 使用与接口

已完成首次改密的 OWNER 登录后，右上角个人菜单进入“屋主工作台”，路由 `/manage/accounts`。默认创建普通用户，也可选择管理员；管理员开户必须重新输入屋主当前密码。其他角色即使直接输入 URL 或发 HTTP 请求也不能开户。旧账号继续用原名称和密码，不被批量改名或强制改密。

| 接口 | 请求与行为 |
| --- | --- |
| `POST /api/auth/register` | 旧路径保留；符合旧 DTO 的请求返回 HTTP 403 / 40300，不调用创建业务；格式错误仍为 400 |
| `POST /api/manage/accounts` | OWNER Bearer；JSON `requestId`（小写 UUID）、`role`（USER/ADMIN）、可选 `ownerPassword`（ADMIN 必填）；成功 `Result<AccountCreationVO>`，`Cache-Control: no-store` |
| `GET /api/manage/accounts/creation?requestId=...` | OWNER Bearer；仅核对当前屋主该请求的成功事实，无记录为 404，不创建账号、不取回密码 |

成功数据包含字符串 `id`、`username`、初始 `nickname`、创建时 `role`、`firstDelivery` 和 `initialPassword`。仅首次事务成功返回 `firstDelivery=true` 与 20 位随机 ASCII 临时密码；重复 POST/确认 GET 固定为 false/null。请求号相同但换角色返回 409；重放不再授予权限，也不重新发密码。

服务端不接受客户端指定账号、昵称、ID、成长或安全状态；这些额外字段无法覆盖服务端生成值。公开 HTTP 注册已关闭，原 `AuthService.register` 仅保留内部历史夹具/兼容调用，所有当前生产 Controller 均不调用它；不得将它映射为新的公开入口。

新账号为 `password_change_required=1`、凭据版本 0、成长初值 0/Lv1/0。临时密码首次登录只进入 P1 受限会话，必须验证当前密码后修改；成功后 PC/H5/PLUGIN 旧会话全撤销，使用新密码重新登录，再按原规则结算每日奖励。

## 发号、事务与密码边界

先锁定操作者用户行，重新核对当前状态、角色、凭据版本、首次改密限制和 Redis 会话；不能把拦截器先前的 OWNER 快照当成写操作授权。随后按当前操作者/请求号核对创建记录，新请求才锁唯一发号行。所有实例共享 MySQL 行锁；只持有操作者与发号行，不锁另一既有用户。少量屋主开户串行执行是有意选择，不是面向批量供应的高吞吐系统。

发号使用 `ph000001` 和“小屋住户000001”，六位以上自然扩展，最多十八位；运行时不扫描最大号。发号推进、BCrypt 哈希用户插入、幂等记录与成功审计同事务提交；失败全部回滚，未成功交付的号码可再次尝试。成功使用过的号码不回收，即使用户软注销；唯一索引和包含软删除的名称检查兜底历史碰撞。成长、登录和头像实现不被开户服务改写。

随机密码来自 `SecureRandom`，不按账号/日期推导；数据库仅存 BCrypt，幂等表和审计没有明文列。DTO/交付 VO 的 `toString` 均隐藏凭据。页面只在组件内存展示密码，离开、换号、退出、确认或卸载即清除；用户主动复制会将密码交给系统剪贴板，应私密交付。浏览器不允许自动复制时可手动选择复制。

`sessionStorage` 只保存操作者 ID、请求 UUID 和创建角色，不保存密码或 Token。刷新后先确认原意图，写请求不自动重发；超时或 503 不能认定账号没有创建。GET 404 也可能是原请求尚未提交，继续核对或用同一编号重试，不另起编号。只有本接口明确的 400（校验/再验密拒绝）才释放未执行意图。创建成功后请先保存；**丢失的初始密码不可恢复，P3 的显式重置尚未交付，此时不要重复开户。**

## 迁移与回退

先备份数据库，再在已完成 001～005 的库执行 [006_account_provisioning.sql](../../polyhouse/sql/006_account_provisioning.sql)，最后启动新后端。不由应用启动自动改表。006 只追加：

- `sys_account_sequence`：固定槽位和下一序号。仅首次初始化从全部历史（含软删除、大小写等价）`ph` 加六至十八位数字的最大后缀确定起点；重跑 `INSERT IGNORE` 不重置已有进度。该迁移初始化与禁止运行时 MAX+1 是不同场景。
- `sys_account_creation`：操作者/请求号联合主键、目标唯一键及初始交付元信息。无外键级联删除，账号注销后仍保留发放事实；当前不清理请求记录，以免旧请求再次产生账号。

同名既存表不会被重建或自动修复不兼容定义，执行前核对表结构；MySQL DDL 隐式提交，备份不可省略。保留 P1 凭据版本、ADMIN 识别与唯一屋主保障。

回退优先使用兼容修复版本；停止新增开户，保留已有用户、发号进度及创建事实，不删表、不降低版本、不把已使用号码重置为 1。直接切回 P1 会重新开放公共注册，不能把它当作安全回退；如确需回退代码，先在入口阻止旧注册且维持新账号首次改密/P1 安全能力。恢复数据需要匹配的整库备份及会话撤销，不能仅恢复序列表。Git 回退不是数据库回退。

## 验证入口

普通验收：根目录 `polyhouse/scripts/Test-Project.ps1`，明确关闭真实实例开关。真实开户测试：

```powershell
.\polyhouse\scripts\Ensure-LocalRedis.ps1
.\polyhouse\scripts\Invoke-LocalAuth.ps1 -Action Verify -AccountProvisioningOnly
```

复用忽略的 IDEA 私有预设，需要本机建临时库权限；仅创建随机 `polyhouse_provisioning_*` 库，迁移 001～006，在其中自建测试屋主。覆盖权限、管理员再验密、同请求并发一次交付、八个不同请求并发发号、审计失败回滚、迁移重跑/历史软删除冲突/六位扩展、会话版本/首次限制及真实改密登录；结束精确清理测试会话并删除本次库。不在真实开发库创建、提权、清空或替换屋主。

可选实际浏览器验收：本机前端在 `http://127.0.0.1:5173` 在线、安装 Edge，并可解析 Playwright 时，将 `POLYHOUSE_PROVISIONING_BROWSER=true` 后执行同一隔离入口；非项目依赖位置用 `POLYHOUSE_PLAYWRIGHT_MODULE` 指定已安装模块目录，不自动安装依赖。测试只启动独立无头 Edge，通过临时代理桥接随机后端端口，不修改 Vite 或个人浏览器；不向浏览器子进程继承数据库/JWT 凭据。遮罩截图和安全结果仅在忽略的 target。
